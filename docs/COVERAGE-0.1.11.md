# SteamSentinel 0.1.11 范围与验收

本版落实本地 Steam 扩面首版，仍供用户在已有环境中验收。不连接样本地址，不运行病毒，不下载其他工坊项目。两个 GUI 只显示正常版本号。

## 已实现

- 本地多库全数字 AppID 发现，非 Wallpaper 项目不要求 project.json。记录工坊 AppID、项目 ID、MOD/插件来源。
- 鸭科夫 MOD 三段已确认 DLL 链按精确哈希覆盖，不以文件名或正常资源同包作为判毒依据。扩展目录适配不等于所有游戏私有 MOD 路径都能自动发现。
- SteamSentinel 保留密码复用与手动启发式隔离，新增 MSI 数据库/CAB 只读读取、LNK 静态字段和有界脚本字面量/Base64 规范化。所有内容解析继续使用受限 Worker。
- SteamSentinel 扩展实际文件绑定的启动项、任务、服务与宿主模块关联，关闭宿主不会隔离正常游戏。服务动作禁用启动并请求停止，不删除服务或操作驱动。
- steamprocess 安全排除项/防火墙恢复只在关联本机恶意插件且快照匹配时提供，需要用户手选。排除项不确定、恢复冲突或上次操作完成状态不明时拒绝覆盖，不重置代理、证书或全部安全配置。
- 对 Wallpaper 举报入口提供双信号启发式复核，建议通过 Steam 验证文件，不用来源不明的备份替换文件。本版没有全部 Wallpaper 版本的官方哈希基线。
- IsMySteamSafe 轻量核对已知内容及关联运行/启动证据，不解包、不询问密码、不隔离，文件风险与 Steam 篡改使用不同结论。支持前次 JSON 报告对比及取证时选择运行历史摘要。
- 拒绝网络路径、ADS、重解析点及越界元数据，资源上限、取消、未展开和读取失败均保留说明。

## 当前验证与限制

开发机自动回归：SteamSentinel 198 项通过、IsMySteamSafe 33 项通过。包含既有密码/管理员启动用例、新增无害 MSI/CAB/LNK、多库多 AppID、MOD 误报边界、已知身份绑定、报告隐私与对比测试。界面采用离屏渲染核对，不启动恶意内容。

本机无害自动回归、只读当前环境检查及 25 输入静态样本批次已完成。样本回归有 16 个输入含已知恶意内容、7 个仅提供人工复核处置、2 个未给出恶意结论，6 个输入仍存在内部未解开或其他覆盖限制。23 个可处置输入不等于 23 个已确认病毒，也不是未知样本检出率。全部 25 个原始文件 SHA-256 与先前基线一致。

MSI 两个案例已从“不展开”推进到读取安装表、Binary/内嵌 CAB，最终运行行为仍未确认，不提升为已知恶意。ungeond.rar、TinyWorld.rar 等未知密码内部仍未检查。

新增服务/关联安全配置的真实管理员处置与回滚，仍需在用户云电脑进行本版验收。本机没有为此修改真实服务、防火墙、排除项或信任存储，没有启动恶意程序。已有安全边界测试不能代替这一步。

间接脚本引用链可发现，但自动禁用入口仅接受直接、可核对的恶意目标。原子文件身份绑定继续保留，服务/计划任务的系统配置 API 没有通用比较交换事务，不声称能消除所有并发修改竞态。未知系统级驻留仍可能需要专业工具。

## 请在云电脑核对

1. 安装新包，分别普通权限/管理员窗口快速扫描，确认安全握手正常。
2. 下载、解压、已执行三个既有阶段分别导出报告，确认文件风险不被写成已执行或 Steam 篡改。
3. 确认非 Wallpaper 工坊、鸭科夫 MOD 与插件出现在来源里，正常 MOD 不因文件类型产生病毒结论。
4. 仅选择预期的恶意目标，核对宿主关闭、文件隔离与启动入口动作，保存逐项成功/失败记录。
5. 从官方客户端补全 Steam 文件，必要时验证 Wallpaper/游戏文件完整性，核对订阅是否会重新下载问题项目。
6. 重启系统后复扫，使用 IsMySteamSafe 对比先前 JSON。对比结果缺失不能单独作为清除证明，覆盖不足时不要永久删除隔离证据。
7. 配置恢复或服务测试只针对确实由测试链产生、已记录基线的条目，不为了凑测试在日常电脑制造安全排除项。

本机清除不能撤回已泄露凭据，有窃密证据时从可信设备更换密码并撤销其他会话。
