# SteamSentinel 0.1.17 受控测试指南

## 先确认拿到的是什么

1. 打开交付目录的 `RELEASE-METADATA.json`。`preview: true`、文件名含 `preview` / `dirty`，或 `SIGNING.txt` 写着 `UNSIGNED-PREVIEW` / `SELF-SIGNED-PREVIEW` 时，都不是正式公开发布。
2. 用同目录的 `SteamSentinel-*-RELEASE-SHA256.txt` 核对程序 ZIP、源码 ZIP、安装器（若有）、SelfTest 结果和元数据。还要通过独立可信渠道确认元数据里的 commit/sourceTree；单独一份同目录哈希文件不能证明发布者身份。
3. 退出所有旧版普通窗口和管理员窗口，再使用完整安装器升级，不要只替换 EXE 或 DLL。
4. 不要关闭安全软件、添加广泛排除项或放宽 Program Files 权限。不要上传压缩包密码、Steam 凭据、支付信息、原始样本或未脱敏报告。

## 本轮无害最小验收

1. **版本与安装**：安装后确认主界面版本为 0.1.17；文件属性中的 ProductVersion 应等于元数据 `buildIdentity`。安装根目录不应残留 0.1.17 以前平铺的 `COVERAGE-*.md`，文档位于 `docs\`。
2. **扫描与取消**：用自行生成的普通文本和无害 ZIP 分别做快速扫描、文件扫描和目录扫描；扫描中取消一次，确认窗口恢复可操作，覆盖状态不把取消当成安全结论。
3. **报告导出**：导出 JSON/Markdown，核对版本、BuildIdentity、BuildId、覆盖状态及耗时；报告不得包含密码或样本内容。
4. **Worker 边界**：普通窗口和管理员窗口各运行一次无害扫描，确认 ArchiveWorker 完成 Low/Untrusted 握手；检查入站/出站阻断规则精确指向当前安装路径。
5. **安装门禁**：便携 ZIP 只允许扫描和导出。真正可写、缺文件、哈希不符或清单权限异常的安装必须拒绝处置，不能靠 UAC 绕过。
6. **提权交互**：第一次取消 UAC，原报告与选择应保留；第二次同意后，新管理员窗口必须重新扫描，不能继承旧窗口计划或密码。
7. **卸载**：确认应用目录和 ArchiveWorker 防火墙规则被移除；隔离证据默认保留，不能把卸载当作安全删除。

## 隔离生命周期边界

当前 Broker 没有可独立验证的完整复扫证明链，因此 UI 显示 `Complete` / Full clean 也不会授权永久删除。测试应确认：

- 任何仍含活动记录的事件均拒绝删除，包括旧版本事件和界面认为“已重启、复扫干净”的事件。
- 只允许清理结构、事件 ID、路径与清单均通过核验，且所有记录已经 `RolledBack` 的空事件。
- 不要为了删除隔离样本而回滚。回滚的用途是恢复经人工确认需要恢复的内容；仍需处置的内容应保留为隔离证据，等待后续具备可验证证明的安全删除机制。
- 回滚目标已存在、身份改变或无法安全绑定时必须拒绝覆盖并保留证据。

生命周期测试只使用无害合成文件和一次性测试事件，不运行或恢复恶意样本。

## 密码与覆盖状态

1. 可用自行创建的无害加密 ZIP 检查输错后更正、跳过与作用域复用；密码不得进入命令行、报告或日志。
2. 未解密、损坏、不支持、超限、读取失败或取消均应保留 `Partial` / 未完整说明，后续文件仍可继续时不得丢失已完成结果。
3. “重试未解密内容”只补查相关外层文件，不代替全机或原范围复扫，也不能解锁永久删除。
4. 在无害嵌套 ZIP/7z/RAR 上分别检查三种复用范围；多密码列表应按输入顺序尝试，保留密码空格。候选未验证不能显示成已验证密码。
5. 选择本次跳过所有未能解密包后，不再反复弹窗，但能用已有适用密码解开的包与普通文件仍继续检查；新扫描应恢复密码询问。详见 [0.1.19 密码交互](PASSWORD-0.1.19.md)。

## 反馈至少包含

- Windows 版本、DPI、账户类型、Steam 与工坊所在盘符。
- `RELEASE-METADATA.json` 中的 version/buildIdentity/commit/sourceTree，以及规则版本。
- 脱敏后的报告、失败阶段、完整中文错误和复现步骤。
- 若卡住，说明发生在扫描、密码、取消、UAC、方案、处置、复查、回滚还是卸载阶段。

不要要求其他测试者执行未知来源文件，也不要把“自动测试通过”或一次干净扫描表述成整机无毒证明。
