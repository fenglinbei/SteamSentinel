## 操作行为

扫描前采集可用物理内存、提交余量、临时卷空闲空间和逻辑处理器数。遇到可调整的预算时，在检查点暂停，显示目标、当前值、建议值、需求是否已知、预计内存/临时空间、预留空间和风险。用户可以保持限制、停止扫描或批准提高；批准不是默认按钮，关闭窗口等于保持限制。中英文使用同一状态和参数。

已知需求以足以通过当前操作的数值为起点，字节额度向上取整到 MiB；未知需求按有界增量（通常当前值的 1.5 倍）提出下一段额度。单成员大小还会联合评估临时、展开和工作量预算。文件声明可能不真实，检查当前操作不等于保证整个剩余扫描完成。字符串检查按流式缓冲估算。此前 AMSI 的整块缓冲估算逻辑保留，但本轮暂停后不调用该引擎，也不产生其额度请求。

批准前再次查询资源，若余量已不足则不应用额度，并留下 `resource.capacity_changed`。用户可在弹窗内重新评估。物理内存与提交余量分别预留，避免把大内存机器的物理预留误用于较小的提交余量。预估保留至少 1 GiB 提交余量、至少 1 GiB 或物理内存八分之一的物理余量，以及至少 1 GiB/原配置二者较大的临时磁盘空间。批准后，临时写入也检查该磁盘余量；未发生提额的旧配置保持原磁盘预留语义。

系统提交余量由 `GetPerformanceInfo` 的系统总量计算，Worker 的 Job 余量单独约束每路内存预留。没有用进程受限的 `GlobalMemoryStatusEx.ullAvailPageFile` 代替系统余量；该区别见 [Microsoft MEMORYSTATUSEX](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/ns-sysinfoapi-memorystatusex) 和 [PERFORMANCE_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-performance_information)。真实受限 Worker 专项验证了多路路径。

授权默认只作用于当前 Worker 的独立选项副本。只有明确勾选保存、且宿主最终批准的额度才保存到当前扫描模式；保存失败会提示。拒绝全局额度后不随文件切换重复询问。每个扫描至多 64 次资源决定，已批准区间内不重复询问。

## 续扫、限制和证据

在受限操作前提高有效额度后继续当前调用，不通过重新启动扫描清零预算。累计读取、解码、展开及当前临时占用继续计账。密码失败清除未成功接受的逻辑成员时，实际读取/解码工作仍计费。结构搜索窗口需要扩大时可以重做该局部搜索，重复读取照常累计。

总文件/目录数、正文读取、快速单文件大小、字符串大小、报告条数/文本、Worker 内存，以及容器的工作量、单项大小、展开量、临时占用、深度、条目、节点、元数据/密码尝试、压缩比、时间、分卷/候选数和结构读取等预算接入授权。AMSI 大小字段保留兼容性，暂停期间不展示其设置、不产生其额度请求，也不据此限制并行。快速优先通道是原有选择策略；可通过提高普通正文额度解除阻挡，不自动扩大所有优先预算。

提额只涉及已发布的额度字段白名单。路径安全、重解析点、句柄身份、格式/完整性验证、协议帧大小、原生解析器不可表示的值等边界保持原判据；访问拒绝、损坏文件和不支持的格式不能用提额变成已检查。原生调用不返回时仍有独立硬超时；资源弹窗等待不计入扫描和宿主超时。强制退出仍只保证保留已经验证交付的检查点。

保留原报告字段，新增可选 `ResourceAudit`：预检、阶段（`Running`/`AwaitingDecision`/`Finished`）、实际最高并发、等待时间和决定历史。决定保存请求 ID、额度键、前后值、目标、时间及稳定原因码，显示文字在资源文件里。报告 JSON、分批回传和合并保留历史；单次 Worker 的历史只能追加，拒绝改写和重复请求。多个扫描合并的存储历史有独立上限。

原因码：`resource.user_approved`、`resource.user_kept_limits`、`resource.user_stopped`、`resource.capacity_changed`、`resource.no_callback`。不新增显示语言字段，不用中文或英文文字判断成功、跳过或授权。

## 并行范围

低占用模式 1 路；自动模式最多 2 路；高性能模式最多 4 路。处理器、内存和提交余量继续约束实际值，500 ms 采样更新；路径元数据/读头延迟偏高时会暂退回单路。

普通文本、脚本和结构已识别、单项不超过 8 MiB 的叶文件可以并行。先持有拒绝写入/删除的只读句柄并识别实际类型，再分配互不重叠的工作量额度。所有分配来自整次扫描的同一本账，任务结束后按实际读取结算。每路有独立扫描上下文和报告，按目录顺序合并。保留的 AMSI 对象仍为延迟构造，本轮暂停策略阻止所有生产扫描路径访问它。接近文件数、节点、正文、报告或工作量额度时退回串行，避免预读抢占剩余额度。

大文件、容器、分卷、密码组、原生安装包解析及恢复内容输出沿用串行流程。因此性能收益取决于语料；不能把普通叶文件的速度推广到大型压缩包。并发不新增子进程，Job 仍限制为一个受限进程；批准内存提高时保留进程数、关闭时结束进程及 UI 隔离限制。

其他优化包括子节点索引、未完成节点集合、节制的内存回收、合并重复路径查询，以及按真实路径长度分配验证缓冲。打开文件的安全校验和结束时重新验证均保留。
