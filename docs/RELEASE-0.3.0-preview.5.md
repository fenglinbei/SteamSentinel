# SteamSentinel 0.3.0 兼容修订 5

更新：2026-10-02。[English](RELEASE-0.3.0-preview.5.en.md)

本轮为 [v0.3.0-preview.5 自签名 Pre-release](https://github.com/fenglinbei/SteamSentinel/releases/tag/v0.3.0-preview.5)，产品版本仍为 **0.3.0**，规则版本仍为 `2026.09.28.1`。重点处理已观察到的旧 Windows CET 初始化失败，并让其他启动及运行时错误留下可回传的本地报告。

## 安装与启动

关闭普通及管理员红信窗口，使用发行页完整的 `SteamSentinel-0.3.0-preview.5-selfsigned-setup.exe` 升级。快捷方式和安装目录保持不变，无需自行选择标准版或兼容版，也不要单独替换 EXE、混用 DLL 或修改系统防护设置。

原生启动器先核验完整文件清单，再启动无业务操作的宿主探针。标准宿主保留 CET；只有探针尚未就绪、出现已知 CET 错误且退出码为 `0x80131506` 时，才允许一次兼容尝试。兼容宿主关闭本程序的 CET 标志，其他安全边界保持不变。系统策略强制 CET 时，兼容宿主也不保证能覆盖该策略。

未知退出、超时、输出异常、完整性错误或兼容探针失败会停止启动并写报告。业务启动后的失败不会触发自动重放；Broker 的预检拒绝与真实业务退出有独立处理。每次启动重新探测，不保存可能过时的兼容模式决定。

## 本轮变化

- 同一个包包含原生入口、App/Broker/Worker 各两种小型宿主，共用一套托管 DLL 和 `.NET 10.0.12`。Broker 仍通过既有 UAC 流程进入管理员上下文，两种 Broker 宿主仍要求管理员权限。
- Worker 仍使用 Low Integrity 受限令牌与 Job Object。安装器为 Standard、Compat 和旧名别名三个路径各建立入/出站阻断，共六条，并复核规则的精确路径与完整阻断条件；卸载按六个保留名称清理。
- 修复超过传统 `MAX_PATH` 的包内元数据路径被误判为缺失的问题；保留逐段重解析点拒绝、全清单哈希和未知可加载文件检查。
- 原生启动失败及托管未知错误生成有界本地报告；托管报告包含可取得的异常链、堆栈和软件/运行时身份，对常见凭据与用户目录信息脱敏。报告不自动上传，错误收集失败也不会递归报错。

详细设计、进程边界和未覆盖情形见[统一启动说明](UNIFIED-STARTUP.md)。此前的弱规则误报修正、旧操作恢复及 AMSI 暂停状态继续保留。

## 出错后回传什么

优先回传错误提示给出的报告文件：

- 启动报告：`%LOCALAPPDATA%\SteamSentinel\Logs\startup-*.txt`，写入失败时尝试 `%TEMP%\SteamSentinel-Startup-Reports`。
- 托管错误报告：`%LOCALAPPDATA%\SteamSentinel\Logs\error-*.log`，必要时尝试 `%TEMP%\SteamSentinel-Error-Reports`。

同时说明发生时间、软件版本和当时操作；发送前查看报告是否包含不希望共享的本机路径。如果原生启动器本身无法运行、系统直接终止进程或日志无法写入，仍需外部诊断脚本与 Windows 事件日志。未知错误报告只保留证据，不会自动把故障归因于 CET。
