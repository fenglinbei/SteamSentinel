# SteamSentinel 0.1.14 范围与验收

## 本次修复

本版基于 0.1.13，处理两类实际反馈：完整内容扫描在大量覆盖记录下停止，以及旧版处置启动项后仍有文件占用或启动项重新出现。没有执行用户病毒样本，不据此保证特定未知变种已经完全清除。

- 重复的读取预算、快速大文件和视频结构检查说明，按原因与根目录合并。保留准确的累计次数和最多四个示例，次数不是去重文件数，示例不是全部文件清单。补查覆盖整个记录根目录。
- 完整内容扫描默认不设整轮哈希字节上限，文件以流式读取。快速扫描仍有 1 GiB 额度和 128 MiB 小型启动文件预留，保留 Low Integrity、1 GiB Job、20 万文件数以及原有解压上限。
- 修复关联目标独立读取预算，以及任务 XML 的安全读取和内容身份绑定，优先检查已识别的关联落点。
- 关联处置前刷新实际文件身份和配置，涉及未检查的候选文件时通过 Low Worker 补查，最多 64 个候选路径、2000 个文件、512 MiB，超出部分需要另行检查。该补查不会运行脚本、程序或压缩内容。
- 关联后的实际动作全部在预览中列出。仅凭名称或同目录关系不扩大清除范围，变更后的配置和文件需重新扫描确认，单次最多 64 个动作，不截断执行一半的计划。
- 使用 Restart Manager 只读查询部分文件占用，显示进程名称和 PID，不强制关闭句柄。目录句柄、受保护进程或查询失败属于未知，不显示为“没有占用”。
- 处置组件验证所选目标的实际状态，并进行第二轮短时验证。主窗口随后进行系统与 Steam 状态复查，阻止直接再次提交旧报告。短时未复现不表示重启后一定不会复发。
- 安全设置恢复读取实际状态，不把 PowerShell 请求返回成功当作防护已启用。第三方杀毒软件、被动模式和权限/策略限制仍需按实际状态解释。

## 普通用户流程

1. 退出旧版，用安装包覆盖安装，不只替换 EXE。
2. 先进行快速扫描。灰色项可点击“进一步检查”，文件删不掉时可点击“查看占用”，内容覆盖不足可选择对应的完整内容补查。
3. 勾选需要处理的项目，查看关联方案，保存工作后确认处置。正常软件可能需要退出，但不会仅因加载关系就被作为恶意文件隔离。
4. 查看实际动作与复查状态。若仍有占用、配置变化或残留，重新扫描生成新方案，不反复点击旧结果。
5. 如果进行了 Steam 恢复准备，从原快捷方式启动官方客户端补全缺失组件。保留游戏和用户数据，不从假客服页面下载修复程序。
6. 重启后再扫描。在“导出报告”中选择“完整记录包”，保存本窗口最近一次处置的扫描、计划、结果和后续复查，转发前核对其中的个人路径。

## 边界

- 没有新增驱动、内核解锁、任意进程树终止、自动永久删除或无限重试。
- 已确认恶意哈希关联和启发式隔离是不同等级，启发式关联处置只开放管理员组件能独立复核的有限规则，其他链条继续说明原因并留证。
- 完整内容扫描指所选范围，不是在线全平台或系统所有位置。受限读取、未知格式、密码、解压上限和未支持的间接启动链仍会形成覆盖缺口。
- 恢复后是否重新下载，还受工坊订阅、安装器再次运行或其他驻留组件影响。工具不自动退订或删除整个游戏库。
- 占用者及回写者无法仅凭旧版结果推断，需要实际系统证据。仍待用户云电脑验证真实样本的处置、重启与回滚体验。

## 回归验证

自动化用例覆盖长路径重复记录、分批协议与计数更新、显式预算/无限默认预算、任务读取、关联身份变化、启发式边界、文件占用诊断、目标重新出现/状态回退以及记录包不包含样本。最终执行结果另附版本验收记录。
