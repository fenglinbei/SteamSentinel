# SteamSentinel 0.2.0 规划：多层容器、分卷与大文件

日期：2026-09-06。状态：用户已接受开发边界，0.2.0 实施中、待验收，完成后交付可用预览包。审计基线为 0.1.19 提交 `1341d4e514352afe4e1e5c145bd049405a7c748b`（`v0.1.19-preview.1` 标签指向该提交）；本规划不代表功能已通过验收。已有代理／证书诊断、未知组件关联与精确处置计划继续保留，真实样本及实机修复验收保留为发布前门槛，其冻结方案不由本专项改写。

实施状态补充：当前候选源码已接入容器父图、MP4/PE 外附范围、RAR/ZIP/7z 有界分卷、五阶段状态、统一资源预算、深层离线签名、补查页面及主动恢复导出，正在以同拓扑和实体大文件验收。已实现方式与仍存边界见 [0.2.0 实现说明](ARCHIVE-IMPLEMENTATION-0.2.0.md)。以下需求、0.1.19 历史断点和 A01–A10 验收条件继续保留；不因源码已落地自动改记为全部通过。

## 1. 要解决的问题与证据

用户反馈 0.1.19 无法完整处理本次 MP4 尾随套包、分卷以及大于 1 GB 的文件。当前已有魔数识别、MP4 尾随检测、递归归档和密码交互，缺口在于受限内容如何继续展开并检查。应分别衡量外层读取、归档展开与最终文件检查，不能把“识别到了”当成“处理完成”。

本次只读取证还原的链为：

```text
文件扩展名 .rar，实际 MP4 + AES ZIP + 额外尾部
  → 加密 pc.rar
  → pc.part1.rar + pc.part2.rar + pc.part3.rar
  → pc.jpg（实际是加密 RAR）
  → pc.exe（RAR 自解压程序）
  → 167 个 Unity 游戏文件
```

| 已验证事实 | 对规划的约束 |
|---|---|
| 原文件 1,642,218,895 字节；ZIP 从偏移 547,636,526 开始，长 1,094,569,044 字节；其后还有 13,325 字节 | 偏移和长度必须由结构验证得到，所有剩余范围均需记录，不能只截第一个魔数字符串或忽略 ZIP 后数据 |
| 中间存在多个超过 1 GiB 的归档成员和三份分卷；所有归档层使用同一用户提供密码解开 | 要同时打通单项、累计展开、深度、分卷和密码复用，单改一处大小常量不足 |
| 最内层 167 个文件共 1,328,827,423 字节，全部 CRC 核对通过 | 验收必须到达最终文件并验证完整性，不能停在分卷清单或 SFX 文件 |
| Defender 未报毒，但 UnityCrashHandler64.exe 为 HashMismatch，资源含再分发者标记 | 病毒引擎结果、签名完整性和恶意性结论分开；不能把未报毒或保留证书当作安全证明 |

证据编号：工作区 `outputs/mp4-tail-20260906-154331`，最新记录为 `解密复查报告.md`、`structure.json`、`sfx-extracted-files.json` 和 `archive_manifest.json`。原始文件 SHA-256：`0c0665fcaa56044dab02d206296d7671472563d05b895a9ffe2d88598e9e25d1`。真实样本、游戏内容、密码及机器路径不加入代码仓库或公开 CI；自动回归使用自建无害替代物。上述记录是人工辅助解析证据，不是 0.1.19 产品端到端通过记录。

## 2. 0.1.19 现状与具体断点

| 现有机制 | 现有限制与要补齐的行为 |
|---|---|
| `Mp4Inspector`、`FileTypeDetector` | 已有顶层 box 与真实格式识别；增加完整边界链、重复/残留片段的可解释状态，不承诺仅凭格式可判毒 |
| `ContentScanner` 的归档与嵌入范围递归 | 默认最大深度 4，单项 256 MiB，累计逻辑展开 2 GiB，实际展开硬上限为 `min(4 GiB, 2 × 配置展开量)`，条目 20,000，压缩比 500；尾随整体复制也增加深度并消耗展开额度，本次链会遇到多处预算边界 |
| 快速／完整内容扫描 | 快速模式对大项及总读取有独立限制；完整模式的整轮哈希预算放开，不等于归档展开预算放开，也不等于所有内容引擎检查过大文件 |
| 现有密码交互 | 已有最多 16 个候选、当前层／当前外层及嵌套／整轮三种范围；成功、错误、跳过和真实尝试预算要延续到分卷组与后续层 |
| 单个归档入口、随机临时文件 | 尚需应用层分卷发现、分组和受控卷解析；嵌套分卷不能因随机临时名丢失逻辑兄弟关系 |
| SFX 的 PE 入口 | 当前正常 `.exe` 首先识别为 PE，未自动转交内嵌归档检查；归档读取器的 `LookForHeader=true` 不能单独补齐这一调度缺口 |
| 字符串与 AMSI | 超过 32 MiB 的文件不进入现有整文件字符串／AMSI 检查；必须明确区分内容哈希、结构解析与引擎覆盖 |
| ArchiveWorker | Low Integrity、单进程 Job 和 1 GiB 进程内存上限应保留；另有约 640 MiB 回收／768 MiB 停止阈值，不能把这些内存阈值误作输入文件大小上限 |
| 当前后续源码的关联补查 | 另有单项 256 MiB／累计 1 GiB 等独立计账；需协调转交大文件专项补查，不能只改主扫描设置后仍在补查阶段静默失败 |

具体数值以交付时固定提交为准；新源码中的诊断与关联能力不追记为 0.1.19 安装包已具备。

同时核对并保留有界性：最多 200,000 个文件，元数据尝试 `min(80,000, 4 × 配置归档条目数)`，整轮最多 512 次密码解码；原有临时磁盘保留量为 256 MiB。当前的 Worker 握手／退出超时不等于解压阶段的墙钟预算，新增大文件策略须独立定义。底层库可能已经支持部分标准同目录分卷，本专项要求的是可验证的应用层覆盖，不能把所有分卷笼统记为此前无法读取。

## 3. 0.2.0 功能要求

### A. P0：多层格式识别与继续检查

- 将顶层文件、嵌入范围、归档成员、分卷组和最终文件建立显式父子关系，记录真实格式、显示名称、实际大小、父容器相对偏移／长度、内容哈希和检查状态。解压出的成员没有可直接换算的原文件物理偏移时明确说明，不伪造绝对偏移。
- MP4 通过 box 边界、ZIP 通过目录和结束记录、PE 通过节与证书表边界等验证候选范围。针对本案覆盖 MP4→ZIP、改名 RAR、RAR 分卷→改名 RAR、PE/RAR SFX→最终成员。
- 加密目录也属于需要解密的内容；密码校验短值通过后，仍需完成读取及格式要求的 CRC／认证校验，才能宣布该层解密成功。解密失败或损坏产物不得作为已验证文件参与下层推断。
- 每层重新按内容识别格式，不受 `.rar`、`.jpg`、`.exe` 扩展名限制；SFX 仅作为 PE 外壳加内嵌归档处理，静态读取其配置，绝不启动 SFX 或其中的 Setup 命令。
- 未知尾部单独保留范围、哈希、已做检查和未能解析原因。正常媒体、合法 SFX、普通分卷作为误报对照；尾随、加密或多层包装本身不新增自动处置资格。

### B. P0：分卷发现、归组与验证

| 计划覆盖的形式 | 行为要求 |
|---|---|
| RAR `name.part1.rar`／`part01.rar`，旧式 `.rar` + `.r00` 等 | 按归档卷元数据验证身份、次序和接续，不能仅按字符串排序；作为本案强制发布门槛 |
| 7z `.7z.001`、`.002` 等 | 区分字节切分与归档语义，按格式要求构造受限可定位的逻辑流 |
| ZIP `.z01`、`.z02` + `.zip`，明确格式的 `.zip.001` 等 | 按磁盘号、目录和偏移语义处理；不能把所有格式当作简单文件拼接 |
| 名称仅为 `.001`、混入其他归档或缺少首卷 | 先判定格式和归属；无法确认时记录待补卷或不支持，不试用无关文件凑齐 |

- 用户选择任一分卷时，在所选文件的同一已授权本地目录内有界查找同组候选，避免同轮同身份、同密码候选因重复入口重复解码。换密码、补卷、内容身份变化等必要重试仍允许并计账。补充目录通过明确的“补充分卷位置”操作纳入；不自动跨盘搜寻或联网下载。
- 外层归档内的兄弟分卷先登记为同一逻辑目录中的候选，再以编号临时文件存储，由卷解析器按验证过的映射提供流；不依赖危险的原始文件名创建路径。
- 缺卷、重复卷、同名异内容、混卷、卷号不连续、损坏、密码错误、权限不足、源文件变化和格式暂不支持分别报告。能够识别但尚未验证的目录条目保持待检查，不接受底层库静默忽略缺卷后的成功状态。
- 卷组身份包含所有实际用卷的文件身份、大小与哈希，防止同路径替换；内容来自多个卷时，报告保留整个组与外层归档的关系，避免同一组重复计入风险。处置仍指向可核验的真实外层文件／卷组，不能把临时提取文件当作已感染落点。
- 密码复用严格继承现有用户选择的范围；同组各卷属于同一逻辑归档，已验证密码可在其允许范围继续使用。失败、取消、跳过和新的扫描会话继续符合 [0.1.19 密码约定](PASSWORD-0.1.19.md)。

### C. P0：大文件与资源预算

- 完整内容检查应让超过 1 GiB 的外层文件、嵌入范围和归档成员进入流式处理；所有大小、偏移、累计量和 IPC 字节计数使用经溢出检查的 64 位值，覆盖 2 GiB／4 GiB 边界。
- 哈希、范围复制、解压和引擎输入使用固定大小缓冲区；不以整个文件的 `byte[]`／`MemoryStream`／单条 IPC 消息传递内容。需要随机访问的格式使用受限范围流或有界临时文件。
- 重构统一预算：分别记录源内容读取、解压实际产生字节、逻辑展开量、密码尝试、峰值临时占用、进程内存和处理时间；将现有不可配置的 4 GiB 实际展开天花板纳入新策略，使配置、执行和报告一致。错误密码可以回滚逻辑结果，实际读取和 CPU／解码尝试消耗不能回滚。
- 复用经过身份验证的范围与临时文件，减少每层重复复制；已不再需要的工作临时文件及时清理，用户明确导出的证据单独保留。磁盘不足、失败、取消、Worker 被终止时保留已完成结果和明确缺口。
- 保留快速扫描的有限预算；用户从缺口中进入完整或大文件专项检查时显示适用额度。原生调用和解码器不响应取消时，由既有 Worker 终止边界收敛，不能让 UI 无限等待；时间预算以大文件实测锁定，并明确协作取消的局限。
- 对字符串、AMSI、签名及其他引擎分别核对其输入上限；能完整计算大文件哈希不等于已完成其他引擎分析。引擎只读前缀／窗口、超限或不可用时单独记录覆盖范围和缺口，不通过整文件缓冲绕过限制。

建议完整／大文件专项配置的工程起点为：单成员 **8 GiB**、逻辑累计展开 **32 GiB**、累计真实读取／解码预算 **64 GiB**、最大深度 **12**、临时文件峰值上限 **16 GiB**；同时受可用磁盘与安全保留空间约束。保留现有 1 GiB Worker 内存、条目数、压缩比和密码尝试硬边界，逐项评估是否需要调整。以上是待性能与资源攻击验收的起始参数，发布前统一锁定并在界面／报告中公开生效值；不得只提高上限而不提供可取消、可计账、可回收的处理路径。

### D. P0：状态、进度与补查

- 每层分别显示已识别、目录读取、解密、完整性校验与内容检查结果；必要下层未完成时，父项保持 Partial。未检出、未解密、未支持、超预算、缺卷、损坏、已取消不混为同一结果。
- 进度显示当前链位置、分卷数、阶段和已处理字节；总量未确定时不制造百分比。大文件读取与解压期间保持界面响应并允许取消。
- “补查所选内容”携带原始外层文件或卷组及相关缺口；补卷、换密码或调整预算后可重新检查该组，不承诺持久化密码或任意位置断点续解码。新结果独立标明时间、身份与范围，不能冒充全机复扫。

### E. P1：深层程序签名与证据保存

- 对最终 PE 成员接入同一内容身份下的离线 Authenticode 结果，区分 Valid、NotSigned、HashMismatch、链不受信、离线条件不足和检查失败。与已有签名实现衔接，避免平行实现互相矛盾。
- 将 HashMismatch 明确展示为完整性异常，可附资源修改与文件身份证据；没有同版本干净基线时不把失效原因归结为单一改动。未签名、厂商证书或合法签名均不单独判定病毒，也不扩大 Broker 权限。
- 提供用户主动导出的“恢复内容和证据”：只读原文件、生成独立输出、非可执行名称、文件名映射、每层 SHA-256、偏移范围及校验结果。显示预计磁盘占用与未完成项，不覆盖已有输出；常规报告导出默认不附带样本。
- 报告、导出包、命令行和日志不包含解压密码；本次取证采用的外部命令行方式不能照搬为产品密码传输方案。

## 4. 实施顺序与代码落点

| 顺序 | 计划改动 | 完成条件 |
|---|---|---|
| 1 | `ScanModels`／Worker 协议、统一预算、范围流与临时文件生命周期 | 64 位边界、计账和取消测试先通过，Low Integrity／Job／网络边界不回退 |
| 2 | `ContentScanner`、`Mp4Inspector`、归档适配器和分卷解析器 | 能从媒体尾随到嵌套分卷与最终文件；各层完整性可核验 |
| 3 | 密码范围、逐层状态、签名结果、主扫描与关联补查转接、UI 和导出 | 同身份、同候选不因重复入口重复工作；遵守当前层密码范围并允许必要重试，未完成状态正确传递 |
| 4 | SelfTest、专项大文件测试、受限 Worker／安装包回归与发布证据 | 下列矩阵通过并绑定同一 BuildIdentity，才将能力写入已支持范围 |

先核验当前依赖实际支持的分卷接口与格式。若需升级或新增解析后端，必须验证来源、许可证、格式支持及受限 Worker 兼容性；不能依赖用户系统里任意版本的 7-Zip／WinRAR，也不能高权限启动样本或绕过现有单进程 Job 限制。MSI/CAB 外部介质属于另一格式适配范围，不随 RAR／7z／ZIP 分卷支持自动宣称完成。

## 5. 发布验收矩阵

| 编号 | 场景 | 必须观察到的结果 |
|---|---|---|
| A01 | 无害 MP4 + AES ZIP + 加密 RAR + 三分卷 + 改名 RAR + RAR SFX，最终 167 个惰性文件 | 到达全部最终文件，逐项 CRC／认证及 SHA-256 对照通过；全链可追溯且不执行任何提取内容 |
| A02 | 本案同拓扑的实体大文件替代物，外层与多层成员超过 1 GiB、累计逻辑展开超过旧 2 GiB、实际展开超过旧 4 GiB | 不再因旧单项／累计硬上限或深度 4 停留于外层；实际读取、内存、临时峰值和时间有测量值 |
| A03 | 1 GiB、2 GiB、4 GiB 附近的长度／偏移边界（含边界前后 1 字节） | 无整数溢出、截断和整文件分配；至少一组非稀疏大文件端到端通过，稀疏文件只用于偏移专项 |
| A04 | 完整 RAR／7z／ZIP 分卷、从任意卷选择、嵌套兄弟分卷 | 正确归组、次序及校验；同轮同身份同候选不因重复入口重复解码，必要重试有独立计账；每种声称支持的形式各有成功用例 |
| A05 | 缺卷、错序、混卷、重复卷、同名异内容、只有中间卷、卷内容损坏 | 给出具体状态和缺口；不串用相邻无关文件，不把部分展开说成完整完成 |
| A06 | 同密码多层、不同密码、错误后正确、三种复用范围、跳过全部、新扫描 | 沿用 0.1.19 行为；错误尝试预算不回退；新会话清空，日志／报告／IPC外命令行无密码 |
| A07 | 压缩炸弹、伪造超大元数据、深度耗尽、磁盘不足、慢介质、取消／Worker 终止 | 有界退出，界面可响应，临时空间可回收，保留已完成证据和未检查对象 |
| A08 | 合法 MP4、合法 SFX／分卷、随机魔数、ZIP 后残留、size=0／64 位 box、损坏边界 | 不凭签名字符串错误切割或直接判毒；size=0 合法延伸至 EOF 时，不凭内部魔数认定尾随；箱体内部隐藏载荷分析另记未覆盖 |
| A09 | 有效签名、自建签名后改资源、未签名游戏组件、离线链不足 | 状态分开，HashMismatch 可见；不把 NotSigned／Unknown 当成已篡改，不单凭完整性异常自动隔离 |
| A10 | 主扫描、关联补查、局部重试、JSON／Markdown／恢复证据导出、长路径小窗口 | 同一内容身份和完成状态一致；深层文件可定位至真实外层卷组；报告不含密码 |
