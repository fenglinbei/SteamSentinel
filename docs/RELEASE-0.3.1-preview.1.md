# SteamSentinel 0.3.1 大规模扫描与病例保存修复

2026-11-09。[English](RELEASE-0.3.1-preview.1.en.md)

本轮产品版本为 **0.3.1**，发布标签为 `v0.3.1-preview.1`，规则版本仍为 `2026.09.28.1`。继续使用 `CN=fenglinbei` 自签名预发布渠道，不改变系统证书信任或安全设置。请从[发行页](https://github.com/fenglinbei/SteamSentinel/releases/tag/v0.3.1-preview.1)下载完整安装包，退出普通及管理员窗口后升级，并重新扫描此前未完成的范围。

## 修复内容

- 修复大量扫描结果分片重复累计同一条工作进程诊断信息的问题。接收端现在按报告当前保留的诊断计费，替换时扣除旧值，拒绝的分片不改变报告或计数。
- 修复用户提高报告文本预算后，接收端仍固定使用 8,388,608 字符上限的问题。初始配置和本次明确批准的增长同步到接收端；工作进程自报设置不能扩大授权。发送端在检查点和最终诊断发送前使用相同预算检查，未批准、停止和资源不足仍保留真实未完成状态。
- 大病例不再要求整份 JSON 塞进单个 64 MiB 文件。新的存储格式将完整病例流式写入不超过 8 MiB 的分片，逐片记录长度和 SHA-256，所有数据完成后再原子提交清单。读取核验结构、顺序、长度、哈希和完整 JSON；保存失败保留之前的有效修订。
- 病例列表的显示摘要可以缩短，完整摘要和原始证据仍保存在病例中。启动恢复按需读取计划与结果，跳过大型扫描对象的构造，同时核验所有分片；保存的计划仍不能被直接重放。
- 读取与保存通过病例锁协调，成功保存后回收不再引用的旧分片。首次保存失败仅清理本次新建且从未提交的数据，已有不完整记录和无关文件保留。

## 数据与兼容性

新版本兼容旧的内联病例，旧病例在下次保存时迁移。**0.3.0 无法读取新保存的分块病例**；需要回退时，先导出完整记录包并保留整个病例目录，不要仅复制 `case.json`。导出包中的扫描报告和病例仍是完整普通 JSON，不暴露内部存储引用，也不附带被扫描的文件内容。

单病例的序列化安全上限为 **2 GiB**，最多 256 个分片。这个边界防止读取无限输入，不代表扫描预算无限，也不等于机器空闲磁盘或内存。单条消息、传输帧、授权、路径与受限进程校验继续生效。旧扫描报告中的风险和未完成状态不会因升级自动改变。

安装器、统一启动器、Low Integrity 工作进程、Job Object、提权 Broker、隔离回滚和规则判定沿用既有安全边界。本轮不增加新的自动处置目标。

## 回归与发行验证

新增重点回归覆盖十万级结果分片、超过旧文本上限的实际序列化传输、预算批准和拒绝、十万级节点病例的保存/读取/更新/导出，以及损坏、缺片、非法清单和提交失败。发行还要求使用最终工作进程扫描至少 60,000 个新生成的无害文本文件，实际触发预算批准，并将同一份大型报告保存、重读、更新和导出。

精确提交、源码树、构建身份、签名和附件哈希以 `PUBLICATION-IDENTITY.json`、`RELEASE-METADATA.json`、`ACCEPTANCE-SUMMARY.json` 和版本前缀 `RELEASE-SHA256.txt` 为准。重点大规模实扫结果单独记录在 `LARGE-SCAN-RESULTS.json`；完整自测、统一启动、Worker 防火墙契约、安装维护及状态迁移分别提供机器可读结果，不把独立专项计数相加冒充一次完整回归。

本轮大规模实扫使用无害测试文件，不代表重新执行真实感染清除或重启恢复验收。Windows 10/11 安装界面、受影响的旧 CET 硬件、物理跨屏及外部安全审计不记作本修订已复测。自签名包没有公共受信任证书链或时间戳，Windows 仍可能显示发布者不受信任。此前兼容修订的具体边界见[0.3.0 修订 5](RELEASE-0.3.0-preview.5.md)。
