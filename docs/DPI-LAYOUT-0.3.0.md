# 0.3.0 DPI 布局修复与验收

当前状态（2026-09-28）：布局修复已随自签名预发布版 `v0.3.0-preview.2` 交付，见[发布说明](RELEASE-0.3.0.md)。下文保留 9 月 23 日构建的证据身份；后续 Windows 10/11 验收单独记录，物理跨屏验收按用户决定暂停，不能将窗口 DPI 通知测试改称跨屏通过。

2026-09-23，修复小窗口展开选项或证据时的结果行裁切，并校正 DPI 布局验收。此变更不扩展状态码、原因码、结构化消息或处置契约。产品与自测程序声明 `PerMonitorV2,PerMonitor`，产品继续使用 `asInvoker`。

原 V3 在宿主 150% 下为 347 通过、10 失败。只校正测量后为 354 通过、3 失败；三项均是结果行空间不足。例如 784×460 的证据展开场景，一行高 38.667 DIP，可视区域仅 36 DIP。固定的页面高度减数无法覆盖文字、边框、进度栏及按钮换行后的实际占用。

产品现在读取表格视口与实际行高，先为完整摘要行及一个物理像素的余量保留空间，再分配选项、证据面板高度。原操作栏继续在固定区域；可展开内容通过内部滚动访问。高度按物理像素取整，稳定布局不重复失效，关闭或脱离窗口的页面不参与调整。选项末尾增加少量滚动余量，使最后一组控件在分数缩放下仍可完整到达。

验收使用生产窗口、模板、资源和无害数据。原生客户区与 PNG 使用物理像素，界面尺寸使用 DIP。每份布局证据同时记录逻辑尺寸、DPI、底层 `HwndTarget` 变换、像素尺寸、原生客户区核验、表格及单元格几何。截图不会再固定按 96 DPI 输出。

跨缩放测试只向自测程序自己的隐藏窗口发送 `WM_DPICHANGED`，要求底层渲染变换与整个控件树的 DPI 一致；不能接受只修改根视觉 DPI、底层仍使用宿主 DPI 的结果。R2–R4 的该类探索记录保留，但不作为跨 DPI 通过证据。实现参考 [Microsoft WM_DPICHANGED](https://learn.microsoft.com/en-us/windows/win32/hidpi/wm-dpichanged) 与 [进程 DPI 声明](https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process)。

像素判据如下：

- 留白：水平允许 0.51 物理像素；垂直留白与内容居中可能各取整一次，合计允许 1.01 物理像素。例如 125% 下配置的 3 DIP 为 3.75 px，实测某个三行英文单元格为 3 px。
- 居中：相对扣除底部/右部分隔线的真实单元格内容面测量，允许 1.01 物理像素。
- 可视性：仅允许边缘取整的 0.51 物理像素；完整像素的裁切仍失败。
- 双行摘要：直接检查两行真实文字均完整可见及行高有界，避免将固定的 38 DIP 当作所有字体缩放下的最低行高。
- 反向验证：零留白、相对配置少 2 物理像素的留白、4 物理像素的错位，以及 2 物理像素的裁切必须被拒绝。

矩阵包含中英文各 100%、125%、150%、175%、200%，每组覆盖五种主窗口视口、扫描活动、选项/证据展开、内部滚动、各表格、密码、处置预览、语言及导出窗口。另在同一窗口中按 100→125→150→175→200→150→100% 切换，检查按钮、完整结果行和布局收敛。

最终产品身份为 `0.3.0+local.dpi-validation-20260923-r8`：完整原生回归 2,240 通过、0 失败、0 跳过；最终 R14 布局驱动运行上述十组矩阵，每组 384 通过，合计 3,840 通过、0 失败。产品二进制在两次验收间未改变，驱动另存哈希。独立校验 117 项通过，覆盖 1,210 张 PNG 的实际像素内容、尺寸、DPI 与原生客户区一致性；另人工抽查中文小窗口、英文活动/覆盖/选项滚动、200% 处置预览和导出语言窗口。

R9 的 `matrix-final-*` 虽通过几何断言，但画面抽查发现透明 PNG；原先仅验证尺寸的 `verification-dpi-20260923.json` 不能作为截图验收。连独立的红色矩形也无法离屏渲染，软件渲染本身未能解决。按照 [WPF MediaContext 的无显示设备行为](https://github.com/dotnet/wpf/blob/main/src/Microsoft.DotNet.Wpf/src/PresentationCore/System/Windows/Media/MediaContext.cs)，只在短期布局导出进程中启用 `Switch.System.Windows.Media.ShouldRenderEvenWhenNoDisplayDevicesAreAvailable` 后，重新导出 `matrix-rendered-*` 并通过非空内容检查。此开关和软件渲染设置只作用于自测命令，不修改产品配置、系统注册表或宿主显示设置。自测现会拒绝透明/单色空图并保存诊断。旧空图与失败记录保留，最终截图以 `verification-dpi-20260923-v2.json` 为准。

最终计数、二进制绑定与截图核验见工作目录 [本轮结果](../../../work/v03-dpi-20260923/RESULT-20260923.md)。旧 V3、原失败记录与每次探索结果均保留，未生成安装器或冻结 RC。

复现单组布局检查（仓库根目录，构建后）：

```powershell
& '.\SteamSentinel.SelfTest\bin\Release\net10.0-windows10.0.19041.0\SteamSentinel.SelfTest.exe' --layout-ui '<新的证据目录>' en-US 175
```

省略最后的缩放参数可运行宿主原生 DPI。完整自测使用 `--results <新的结果文件>`；其文件身份与受限进程项目需要真实 Windows 权限语义。本轮沙箱中的提前失败与原生执行对照分别保存。

本机是 Windows 构建 26200.9445、单显示器、原生 150%。其他比例是具有一致底层渲染 DPI 的窗口通知测试，未修改宿主缩放。单显示器环境不能提供跨物理显示器拖动的证据；Windows 10、多显示器、远程桌面及后续正式候选安装后的验收仍按发布范围补齐。
