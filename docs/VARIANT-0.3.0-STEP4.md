## 已实现的检测

### 原生组件与托管外壳

`VPetFamilyDecoder` 使用独立文件布局解析器校验 PE 节、RVA、单 ordinal 1 导出和观察到的尾部结构。仅在支持格式内还原 `.rdata`、`.data` 两个非执行数据区，代码区保持原样；派生缓冲只存在内存中，用后清除。扫描不加载程序集、映射可执行映像或调用入口。PE 地址转换依据 [Microsoft PE 格式说明](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)。

- 固定上限：原生输入 8 MiB、代码节 1 MiB、累计变换数据区 4 MiB、最多 96 个节；另受本次扫描工作量、展开量、字符串、时间和取消预算限制。
- 校验重复节、原始范围/RVA 重叠、区间越界、异常尾部、导出指向和角色一致性。失败保留原因码及 `Partial`/`LimitReached`，不会把“不能解码”标为成功。
- 识别加载器的两项配置名，并复用既有字符串检查器检查派生内容。UI 载荷要求 PX 标记及客服路由组合；凭据载荷组合包含内存读取、凭据解保护、Steam 本地数据及上传接口。未知代码需同时命中已知家族域名和组合语义，单个 API、文件名或域名不足以触发新家族结论。
- 已知代码节但尾部损坏时保留家族复核提示，同时保留解码与未知尾部缺口。已知原件仍按完整 SHA-256 命中既有精确规则。
- `VPetWrapperInspector` 仅读取 ECMA-335 元数据与 IL，识别本批外壳的 VPet 入口、后台回调、原生 ordinal 调用及原依赖委托组合，包括天籁之音采用的 `AssemblyLoadContext` 路径。输入上限 2 MiB，类型/方法/成员引用分别上限 512/4,096/8,192，单方法 IL 上限 16 KiB。

`VPetFamilyEvidence` 分开记录原件 SHA-256、代码节 SHA-256、派生 SHA-256、数据区位置、解码器版本 `VPET-20260919-1`、角色、稳定信号码及已扫描关联节点。数据通过受限 Worker 的有界报告协议校验，并在容器详情、Markdown 和 JSON 中保留。派生哈希不成为原件隔离身份，报告不携带派生字节。

### 同一 MOD 内的关系

完成一个扫描根后，只对本轮已读取并取得哈希的文件建立关系：外壳 → 同 MOD 的加载器 → 配置指定的两个载荷；同时记录实际存在的原依赖、`info.lps` 和可选 `.px_sidecar`。

关系受父容器和实际路径限制；同名嵌套归档、不同 MOD、名称歧义不会合并。扫描元数据中的文件名不会触发额外文件读取，声明的 Workshop ID 不替代目录身份。单独选择一个组件时，不推断其他路径已检查。`.orig.dll` 只表示委托关系，不能作为可信恢复原件；静态关系也不能证明组件已运行或凭据已泄漏。

### Steam HTML、JS、CSS

`SteamSecurityScanner` 读取 `steamui`、`clientui` 的 JS/HTML/CSS 及 `resource/webkit.css`。每个文件通过拒绝写入/删除的只读句柄取得同一字节快照，校验最终路径，严格 UTF-8 解码并计算 SHA-256。关联检查只使用这些本地快照。

| 新规则 | 依据 | 结果 |
|---|---|---|
| `VPET-FAMILY-STRUCTURE` | 已知代码节、托管调用结构或支持封装中的解码语义组合 | 高风险、供复核 |
| `VPET-STEAM-UI-PROVIDER` | 真实 PX 块内的两个全局路由属性定义和已知家族 URL 主机 | 提供脚本已观察到；路由关联未建立 |
| `VPET-STEAM-UI-CHAIN` | 实际 chunk 的客服路由引用与同 UI 根的提供脚本匹配 | 记录逐文件关系及哈希；HTML 引用、CSS 隐藏作为附加证据 |

三个新规则均为 `IsKnownMalware=false`、`CanRemediate=false`、`ReviewOnly`。现有完整恶意哈希规则及既有 Steam 规则的权限未扩大。

- 支持 `window`、`self`、`globalThis` 的直接/方括号属性引用；处理注释、字符串及常见正则字面量，避免文档示例被当成路由代码。URL 比较主机，路径和用户名中出现域名不算命中。
- HTML 的 `/sp.js` 只对应所读 UI 根中的文件；不访问外部 URL，不跟随穿越、网络路径、重解析点或编码路径。超长引用、超限或不支持的相对 `base` 情况保留缺口。
- 单文件 32 MiB、每个 Steam 根累计 256 MiB；每个 UI 目录最多 2,000 项，关联事实最多 512 个文件、单文件 64 项引用/路由/定义、32 个 PX 标记、最多 64 个结果。PX 块上限 256 KiB；正则采用非回溯引擎并有时间上限。
- 日期或远程条件只记录为“已观察到门槛，未判定当前激活”。不执行脚本、不改变时钟、不请求真实端点。仅 HTML 引用、CSS 隐藏、普通日期判断、同名 `sp.js` 或 Millennium 目录都不足以触发新家族规则。

这不是完整 JavaScript 解释器，也不是任意 PE 解包器。重写元数据类型、改变封装算法或使用未支持的计算属性/动态代码时，不承诺沿用本次家族识别；支持范围内的静态检测通过不代表所有潜在变体均被覆盖。

## AMSI 的新增证据与未完成项

本次只读枚举发现宿主注册的 AMSI 提供程序为 Norton，服务器为 `symamsi.dll`（版本 `15.7.14.33`）；宿主 WinDefend 服务未运行。最终构建对固定无害文本及官方 DLL 的 Medium 探针仍在 ScanBuffer 阶段返回 `0x80040300`，Low Worker 对两个 DLL 返回 `0x80070005`；初始化和会话均成功。

这与此前干净 VM 中 Defender 环境的无害独立探针成功属于不同条件，不能合并推断原 VM 根因。本轮没有停止 Norton、关闭防护、提升 Worker 或改写 Partial。RC 前仍需在一次性干净克隆中对齐提供程序、账户、完整性级别和同一构建，完成 VM 中的根因定位与修复验收。封存基线保持不动。
