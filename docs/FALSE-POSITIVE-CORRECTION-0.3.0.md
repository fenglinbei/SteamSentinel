# 0.3.0 弱证据误报修正说明

更新日期：2026-09-28。[English](FALSE-POSITIVE-CORRECTION-0.3.0.en.md)。本文说明当前修正的原则和范围，不代表候选安装包已完成验收或发布。下载身份、实际验收结果和发行状态以 [0.3.0 发布索引](RELEASE-0.3.0.md) 为准。

## 为什么修正

正常程序的资源、帮助文字或库文件可能同时包含网址、验证提示和命令名称。此前的通用脚本规则会跨整个文件累计这些词，将相互无关的字符串组合显示为高风险部署链，并允许用户选择隔离。文件里存在这些词语，不能证明发生过下载、执行或恶意行为；DLL 内含脚本相关字符串也不表示整个 DLL 是脚本。

## 修正范围

- 通用词语共现改为中风险、仅供复核，使用 `HEUR-SCRIPT-TOKEN-COOCCURRENCE` 和稳定原因码 `ScriptTokenCooccurrenceOnly`，不授权文件隔离。
- MSI 的通用静态声明、快捷方式目标和参数、运行历史中的同类词组合保留观察结果，不因词语共现取得处置资格。静态声明与历史文本均不证明实际执行。
- 仅由弱文件观察得到的进程或模块关联保留为诊断信息，不据此将正常宿主标为已加载恶意组件，也不授权终止宿主。
- `.node` 作为 Windows 原生模块的常见扩展名，与有效 PE 格式兼容；仍检查文件内容、哈希和其他风险。该修正没有把所有 `.node` 文件列为可信文件。
- 仅匹配历史落地路径但未命中精确恶意哈希时，显示低风险路径观察；文件名或目录名相同不代表恶意身份相同。

精确恶意哈希、既有专用强组合、VPet 有界家族识别和独立配置证据继续按各自规则处理。同一文件另有当前规则库确认的精确恶意哈希时，使用独立哈希证据，而不是恢复旧弱规则的授权。未知 VPet 家族结构原有的复核边界也不会因此放宽。

## 证据如何显示

共现结果只保留有界数量的固定词、编码和解码窗口起始位置，不复制任意邻近原文。窗口位置不是词语的精确字节偏移；有界字面量拼接或 Base64 还原后的观察会说明经过规范化。这些信息帮助定位来源，不证明控制流、数据流或执行顺序。扫描不会为验证这些词语而运行脚本、快捷方式或提取出的程序。

## 旧报告与重新扫描

旧报告和病例保留原文、当时分数、时间及结果，不批量重写历史记录。修正后的界面和新计划入口会拒绝退役的通用弱规则，即使旧报告曾标为可隔离或高分；批次会保留未纳入原因。

请使用包含此修正的版本重新扫描原范围，以新结果判断当前文件身份及处置资格。原报告可以保留用于比较；重新扫描不会自动恢复已隔离文件，也不会撤销已执行动作。需要恢复时，先核对原目标及隔离原因，再按现有回滚流程处理。

## 管理员处置边界

本轮修正加强了界面选择、关联证据和新计划生成的资格判断。管理员 Broker 仍核对既有计划绑定、允许范围、精确路径与文件哈希，并保持文件操作的锁定句柄约束。

通用文件隔离目前仍不对每条扫描结论做管理员侧独立恶意性重判。本轮没有引入高权限归档解析，也不宣称建立了完整的报告防伪证明。进程和持久化入口原有的独立强内容复验保持各自范围；不能把这些有限复验描述为对所有文件与容器均适用。

“仅供复核”不等于“已证明安全”；已确认恶意内容和未完整检查的内容也不会因修正误报而被隐藏。使用步骤及隔离、报告和回滚边界见 [README](../README.md) 与 [English quick start](QUICKSTART.en.md)。
