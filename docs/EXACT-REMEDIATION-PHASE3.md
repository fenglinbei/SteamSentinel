## 独立授权与精确目标

新增 `RemoveBoundCertificate` 和 `RestoreBoundProxyConfiguration` 两类动作及类型化计划构建器。规则必须随构建提供经审核的精确目标指纹、来源工件 SHA-256 和证据引用。Broker 独立检查规则、目标身份和请求者 SID；客户端的严重度、`IsKnownMalware`、关联字段及用户可写病例都不能授权配置修改。

规则若声明已确认写入组件，计划还必须绑定该组件的精确路径、哈希及对应隔离前置动作。未确认写入者的规则不能通过客户端字段补写“已查明来源”。证书规则识别存储位置、存储名与 DER；实际动作另绑定当前属性指纹。代理规则识别完整的前后快照和允许修改的字段。已知恶意文件的既有 Broker 权限继续独立核验。

## 证书删除与恢复

目标限定为当前请求者 SID，以及 `CurrentUser` 或 `LocalMachine` 的物理 `Root` / `CA` 注册表证书库，使用 `CERT_STORE_PROV_SYSTEM_REGISTRY_W`。不通过继承后的逻辑集合按名称删除。必须精确匹配 DER SHA-256 和已枚举公开属性指纹；同 DER 多个上下文、未知属性、私钥相关属性或读取不完整均拒绝处置。

先备份公开 DER 及允许恢复的公开属性，再重新打开和同步物理库，重核目标、属性及变化通知。删除绑定取得的原生证书上下文，随后再读取目标状态。属性白名单为 3、4、9、11、13、19、20、27、107；先审查属性 ID，未批准的值不读取。每份 DER 最多 128 KiB，公开属性合计最多 256 KiB、32 项；物理库枚举另有数量、字节与时间预算。

恢复先在内存证书上下文设置并核验所有属性，之后使用 `CERT_STORE_ADD_NEW` 一次加入物理库。相同 DER 已存在时拒绝恢复，不覆盖之后合法加入的证书。内存属性 ABI 测试覆盖全部白名单，包括使用 `CRYPT_DATA_BLOB` 传递日期戳属性；该测试不打开或写入系统证书库。

Windows 这些接口不提供“DER 与属性版本比较后原子删除”的事务。前后重核和通知缩小并发窗口，不能消除最后一次检查到删除之间的竞争；无法确认时保留失败或未知，不承诺原子比较交换。

## 当前用户 LAN 代理修复

首个支持范围是 `WinInetCurrentUserLan`：通过 WinINet 按连接选项接口、空连接名明确读取和写入当前用户 LAN 配置。目标保存 Flags、ProxyServer、ProxyBypass、AutoConfigUrl 的原值、预期新值及字段是否存在，并保存策略检查指纹。只提交计划列出的修改字段，其他值与未知标志位保持原样。

执行前再次核验当前用户、完整配置和策略状态；原值变化、策略接管或策略不可读均拒绝旧计划。检查包括对应用户与机器的 Internet Settings 策略、IE 控制策略及 `ProxySettingsPerUser`。本批不支持机器级代理修复、WinHTTP 修复、其他连接及受策略管理配置，不通过扩大通用注册表删除范围实现。

写入后发送配置变更及刷新通知，再读取完整 LAN 配置核对预期值。记录写入是否尝试、通知是否完成、读回是否匹配和 `Prepared`、`Unchanged`、`Applied`、`Indeterminate`、`Restored` 状态；未匹配时的完整实际读回快照目前不另行保存。通知失败不能报告执行成功；读回混合状态保留未知。回滚要求当前完整配置仍精确匹配本次已应用的状态，否则拒绝覆盖后续变更。

这里验证的是 WinINet 配置与接口通知，不宣称已经证明每个运行中应用的实际网络流量路径。最后一次完整快照、策略核对与 WinINet 写入接口之间仍存在竞争窗口，该接口也不提供原子比较交换。新值必须来自规则确认的安全差异；没有干净基线时不能凭空构造“感染前设置”。

## 备份、依赖与结果恢复

关联动作保存链 ID 和前置动作 ID。Broker 根据精确路径、文件哈希、进程身份及显式关系重新构建依赖，并拒绝重复、缺失、循环及不合法顺序。客户端删除依赖字段或给同一文件换路径别名不能绕过已识别的关联链。

所有配置备份在本计划首次变更前完成并持久化。某链备份失败时阻断整条链；其他独立链仍可执行。停止进程、解除持久化、隔离组件之后，只有前置动作执行成功且即时复验为 `Verified` 或 `NoResidual`，才继续依赖的配置修复。失败、未知、复现、待重启均不能放行；下游保存 `SkippedDependency` 和具体原因。

配置备份位于既有受保护隔离事件内，使用有大小上限的不可覆盖版本文件，清单保存受事件根、动作 ID 和内容哈希约束的完整版本路径及 SHA-256，并由既有受保护清单机制约束。载荷绑定计划、事件、动作、SID、规则、目标和备份。写入前先持久化尝试标记，修改后再保存观察到的状态。磁盘提交失败造成执行状态不确定时记录 `ExecutionUnknown`，旧可信备份版本保留。恢复只读取清单绑定的版本，并重新核对身份、哈希和目标。

清单另保存实际动作顺序，回滚按其逆序执行，避免备份记录提前插入导致配置与文件恢复顺序错误。新配置动作缺少可信顺序时拒绝回滚；既有旧清单保持原兼容路径。每计划最多 64 个动作，其中配置动作最多 16 个，计划最大 1 MiB；单份受保护配置备份最大 768 KiB。

主程序启动 Broker 前先把未决计划持久写入病例。超时、退出但没有可信完整结果、或执行状态不确定时保持未决并阻止新处置，重开应用也会恢复这一门槛。读取病例后，仅从固定受保护 Broker 结果目录恢复匹配的计划结果，检查 SID、权限、文件身份、计划 ID、完整类型化计划指纹、动作和完成状态；每次写回另一份病例也重新核验完整计划。修改病例中的注册表值名、进程启动时间或代理预期值不能套用原成功结果。旧版结果没有完整计划指纹时保留未知，不能支撑新的跨会话通过结论。旧计划不会自动提交或延长有效期。

## 病例页与跨会话复验

界面新增第六个“病例复验”页，提供读取病例、复验所选病例和导出病例。确认处置后保存原扫描、内容范围与设置、计划、动作结果、未决计划及处置前会话基线。病例位于当前用户的 LocalAppData，通过有版本号的原子更新保存；索引丢失可从实际记录恢复。病例是用户侧调查记录，不是管理员处置授权，也不保存归档密码。

新会话依据同一用户的启动事件及交互登录身份核验：系统启动使用 Kernel-General 启动事件；登录使用令牌 AuthenticationId 与 LSA 登录信息，并处理关联令牌及交互 Shell 身份。重开窗口、普通进程 PID 变化或 UAC 提权不算重新登录。需要重启的目标必须得到新启动证据；转换发生时间还必须晚于本次全部已执行动作的完成时间。事件不可读、日志重置或身份不一致时保留未知。

每次复验追加独立记录，不改写原即时结果。核对精确目标，再以原内容设置调用受限工作进程，并重新运行当前入口、宿主、模块与组件关联检查。只有原内容范围、必需来源和复验前后会话身份都满足要求，才可显示“所选目标跨会话复验通过”。原 PID 不存在只说明原进程身份消失，不能排除新宿主或写回来源；此前清除的目标再次出现时记录 `Reappeared`。

界面分别显示未决执行、等待新会话、会话未知、复验不完整、残留、复现和所选目标通过。当前实现始终保留“写入来源尚未证实”，不输出整机清除结论。存储最多 128 个病例，每病例 64 MiB、512 个计划、32768 个动作和 32 次复验；启动恢复共用 128 MiB 读取预算，失败或超限时阻止新的处置。一次复验默认 2 分钟，最多 256 个目标，单目标 4 秒，会话读取 6 秒；取消或超限保留缺口。同步原生调用的时间预算不能保证强制中断正在执行的本机调用。

病例导出包新增 `remediation-case.json`，保留原范围、执行和各次复验元数据，按照现有规则隐藏已识别凭据。导出不打开或复制证书/代理备份载荷、隔离文件或样本；恢复仍使用本机受保护事件流程。
