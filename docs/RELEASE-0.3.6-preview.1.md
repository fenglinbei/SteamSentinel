# SteamSentinel 0.3.6 — 守护链清理与结果页升级

规则版本 `2026.11.17.1`，发行标识 `v0.3.6-preview.1`。本次整合 PowerShell watchdog 清理、临时 CMD 更新链处理与结果页分组，并包含此前 0.3.4／0.3.5 本地预览的 Steam 脚本修复、处置模式和配置修复。

## 更新链清理

- 新增已核验的主程序、内嵌 Core、watchdog、更新器与启动器的精确 SHA-256，覆盖有／无 UTF-8 BOM 的资源和落地脚本，以及与更新器相同的 `update.ps1`。
- 在已确认的安装范围内关联 `%ProgramData%\SteamAlertUpdater` 和驻留目录的 `Updater`，检查固定更新缓存、`.new.exe`、`.old`、`.bak` 和顶层脚本；下载目录内的样本不能单独授权清理本机安装项。
- PowerShell 的 `-WindowStyle Hidden -File` 调用可绑定到具体恶意脚本。管理员执行端重新核对脚本与系统宿主的字节、完整命令行、PID 和创建时间，固定进程句柄后只终止预览中的实例。系统 PowerShell／CMD 文件本身不被隔离。
- 对 `sa_update_<PID>.cmd` 核对整份替换、重启、回退模板和实际恶意程序副本。模板或文件名本身仅作为复核线索；满足完整证据后才纳入预览。隔离时锁住作为证据的脚本和程序副本，并再次核验。
- 同一更新链保持依赖顺序：停止 watchdog，再停止已批准的子脚本与 CMD，移除绑定的自启动，停止驻留程序，隔离脚本和更新副本，最后隔离主程序。执行端自行重建依赖，不信任客户端提供的链标记。
- 每步操作前重新检查文件、运行实例和 Run／RunOnce。预览后出现的新实例、新组件、未知替换文件或不可读状态会停止后续清理，要求重新扫描，不会自动扩大终止范围。复核检查新 PID，文件已删除但解释器仍在运行不能视为清理完成。

## 扫描结果页

结果页分别统计重点项与参考信息。单纯文件格式差异默认折叠，分数移到详情；同一文件有强证据时仍在重点项中展示。“全选重点项”只选择当前重点结果，折叠的参考项不会被批量勾选。保留完整报告、手动展开查看、模式切换和扫描未完成状态。

## 使用与验证

安装完整包前退出 SteamSentinel 和管理员确认窗口。不要混用旧版 EXE／DLL；核对发行附件中的 `RELEASE-METADATA.json`、`SELFTEST-RESULTS.json`、签名说明与 SHA-256 清单。旧扫描结果需重新扫描后再准备处置，不重放旧计划。

源码自测增加命令行解析、正常 PowerShell／CMD、PID 复用、命令变化、预览后新实例、安装范围隔离、脚本和更新副本覆盖、临时 CMD 强证据与执行依赖等回归。可用 `SteamSentinel.SelfTest.exe --steamalert-watchdog-tests <输出目录>` 运行无害夹具专项。显式的 `--steamalert-watchdog-samples <输出目录> <样本路径>` 仅静态读取已知哈希样本，不运行它。

此次恶意样本仅作离线字节和元数据检查，未执行样本、未连接样本服务器。自动化测试与静态样本验证不等同于真实感染主机上的清除、重启及十五分钟更新周期验收；尚未识别的变种会保留复核或阻断状态。

本包继续采用自签名 Preview 标识，不具备公共受信任证书链，不导入信任证书或修改系统信任设置。最终构建身份、测试计数与包哈希以发行附件为准。
