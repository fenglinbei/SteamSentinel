# SteamSentinel 0.1.17 安全与发布工程范围

本版基于 0.1.16，重点处理隔离事件生命周期、受限 Worker 工作区和发布可追溯性。检测规则版本仍为 `2026.09.04.2`；没有因为工程版本升级而扩大恶意判定，也没有执行待检样本。

## 发布身份与依赖

- `Directory.Build.props` 是人类版本号唯一来源：`VersionPrefix=0.1.17`，程序集与文件版本为 `0.1.17.0`。
- `BuildIdentity` 在语义版本的 build metadata 中记录完整 commit 与 `release` / `preview` / `dirty.preview.<sourceTree>`。报告、程序文件属性和发布元数据使用同一身份。
- `global.json` 精确固定 .NET SDK 10.0.400；五个项目均提交 NuGet lock file。CI 与发布脚本只做 locked restore，并把 NuGet 高低级别漏洞公告作为错误。
- Windows CI 保存机器可读 SelfTest 结果，最低基线为 477 项通过、0 失败、0 跳过，同时核对版本与 BuildIdentity。

## 不可覆盖的两阶段发布

- Preview 与 Release 使用不同名称和默认目录。所有程序、测试证据、源码、安装器、元数据和哈希先在输出根下唯一暂存目录生成；成功后才移动为最终目录。
- 脚本没有 `ReplaceExisting`。目标存在即失败，不删除或改写旧的 0.1.16 输出。
- 源码 ZIP 由 `git archive` 生成。干净构建使用 HEAD tree；显式 dirty Preview 先拒绝不在代码/项目/锁文件/文档/脚本/CI 白名单内的未跟踪文件，再用临时 Git index 固化快照并从该 tree 构建与归档。忽略的凭据、二进制和样本不会被工作树复制逻辑带入。
- Release 只接受完全干净的工作树、精确匹配中央版本的签名注解 tag；Preview 即使签名也不会获得正式名称。

## 签名和安装

- Preview 可以明确未签名或自签名。Release 必须使用非自签、Windows 链与撤销检查通过的 Code Signing 证书，以及显式 HTTPS RFC 3161 时间戳；文件、安装器或卸载器任一签后检查失败都会中止。
- 安装器最低系统改为 Windows 10 build 19041，与应用目标一致。文档保持 `docs\` 目录结构，升级时删除旧包遗留在应用根目录的已知文档副本。
- 安装器不会把既有 `%PROGRAMDATA%\SteamSentinel` 目录视为已经安全迁移；异常既存目录及旧未索引事件不会自动受信。Broker 在首次使用前先验证所有者与 ACL，只对能够安全创建或收紧的对象继续操作，否则 fail closed。
- 当前没有自动更新器，也没有签名规则更新、撤回、透明度或防版本回退流程；这些仍是公开发布阻断项。

## 隔离生命周期边界

新事件使用 HKLM 64 位视图中的受保护索引绑定事件 ID、计划 ID、请求者 SID、创建时间、随机 TrustId 和清单哈希。清单更新使用提交/待提交哈希日志；任何已有 ACL 不可信或无索引的事件都不自动采信。请求者仅可读取自己的事件元数据，隔离载荷只授予管理员和 SYSTEM。

处置启动前用 CreateNew 保留一次性 PlanId 结果通道，另用机器级文件锁串行化不同计划。动作记录只有在成功后才标记已确认；不确定状态拒绝自动回滚。由于用户可写父目录的竞态尚无完整安全恢复协议，整目录自动回滚被关闭，保留隔离副本供可信恢复环境人工核对。

当前不存在 Broker 能独立验证、不可伪造的“完整复扫干净”证明。界面的 Full clean 策略只能帮助用户理解状态，不能授权永久删除。因此 0.1.17 采用 fail-closed 规则：

- 任何仍有活动记录的隔离事件都拒绝删除，旧版本事件同样如此；
- 只清理结构、事件 ID、路径与清单全部核验通过，且所有记录均已 `RolledBack` 的空事件；
- 不应为了删除隔离样本而回滚。回滚仅用于恢复经人工确认需要恢复的内容；仍需处置的隔离内容应保留为证据。

这意味着 0.1.17 主动牺牲永久删除便利性，直到后续建立 Broker 可验证复扫证明与安全删除协议。

## 扫描覆盖与资源边界

- Quick 未完整读取的大文件、扩展名为归档但魔数损坏的文件、显式排除根以及 Steam UI 超限枚举都标记 Partial，不产生“检查完整”的假象。
- 多个扫描根共享归档展开预算；错误密码回滚本次逻辑条目/字节计数，但实际展开字节和元数据尝试计数不可回滚。目录成员也消耗条目限额。实际字节最高为 `min(4 GiB, 2 × 配置展开限额)`，元数据尝试最高为 `min(80,000, 4 × 配置条目限额)`。
- 不再先行调用 `Entries.Any` 或 archive 级 `IsEncrypted` 遍历归档；按受限成员循环判断加密。SharpCompress 7z 首次访问 Entries 仍可能在库内部物化目录，继续依赖 Worker 的 Job 内存限额，不宣称完全流式。
- 文件哈希在读取期间执行上限和稳定性检查；PE 识别核验 DOS 偏移及 PE 签名，但这不是完整可执行文件合法性验证。常见 Office/ZIP 扩展名正常化、合法 `./` 成员前缀、域名边界和 UTF-16BE 降低遗漏/误报；规则载入拒绝重复或无效内容。

## Worker、界面与导出

- 低完整性进程通过显式继承列表只接收协议句柄。每轮使用父进程持有租约的独立工作区，展开前保留磁盘余量，结束/取消后清理本轮嵌套内容；未知旧目录不自动删除。
- 取消通过协议传达，宽限期后才终止只读 Worker。密集进度限流但保留阶段切换，已交回的检查点和既有系统/内容发现不会被附加检查失败覆盖。
- 管理员处置等待超时不会强杀 Broker；未解决计划阻止新处置，结果可重新检查。未处理界面异常进入只读恢复模式，报告仍可导出。
- JSON/Markdown/记录包保留构建身份；导出失败或取消不覆盖旧报告。小屏窗口可滚动访问内容，密码输入及范围选择补充辅助功能名称。

## 本轮验证边界

允许运行编译、完整 SelfTest，以及只使用程序生成的普通文本/ZIP 的 Worker 扫描、取消和报告导出 smoke。禁止执行恶意样本、修改安全软件、签名、安装、覆盖历史输出或对真实隔离区做生命周期操作。安装态 UAC、升级、卸载、防火墙规则、DPI/辅助功能和公开签名仍须独立环境验收。
