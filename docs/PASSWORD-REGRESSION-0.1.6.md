# 0.1.6 密码交互与解包异常回归

## 修复范围

针对用户反馈的不同压缩包反复提示密码、无法判断失败原因，以及 `ArchiveOperationException: Cannot determine compressed stream type` 导致整次扫描失败的问题。

| 情况 | 0.1.6 行为 |
|---|---|
| 同密码的不同 ZIP/RAR/7z | 已验证密码按用户选择复用 |
| 部分大文件被跳过 | 已完整读取并验证的加密成员可证明密码可用，未扫描成员仍保留 Partial |
| 只读到了普通成员、所有加密成员均跳过 | 不将密码当作已验证，不加入成功缓存 |
| ZIP 长度或非零 CRC 校验失败 | 不缓存此次未经验证的密码，保留未完整读取结果 |
| 输错 AES ZIP 密码 | 明确提示并允许更正，不再被格式探测包装成未知归档后中止扫描 |
| 同一内层包在多个外层中出现 | 按 SHA-256 记住本次失败候选与跳过状态，每处仍记录覆盖缺口，不重复打断 |
| 后续取得另一成功密码 | 对之前跳过的相同内容仍可自动尝试未试过的新候选 |
| 想主动补充内层密码 | 点击“重试未解密内容”，重新扫描相关外层文件，需要重新输入密码 |
| 单个坏包或不支持的格式 | 标记覆盖缺口并继续其他文件，不据此认定安全 |

验证缓存最多 8 项，失败/跳过内容历史最多 512 个哈希，每个哈希最多保存 16 个失败候选，仅在当前扫描内存中。新扫描重新开始，密码不落盘、不写入报告、不通过命令行传递。

## 已完成验证

- 本地自动回归 86 项，全部通过，无跳过。
- 四类格式分别验证错误密码更正与作用域保留，不依赖只测试本机某一种解包工具。
- 实际 Low Integrity + Job 工作进程测试损坏包、错误密码、后续正常文件和密码提示协议。
- 默认窗口与较小窗口的 WPF 离屏检查，失败原因优先显示，长路径可以展开，重试按钮与版本号可见。
- 真实样本仅静态读取，没有执行样本、访问样本接收端点或调整系统防护设置。

## 真实样本结果

2026-09-04，将用户提供的 25 文件目录作为一次自定义内容扫描输入，共读取 9,614 个归档条目。23 个输入有可选处置项，各输入的已知威胁项数及可选处置项数均与 [0.1.5 基线](SAMPLE-COVERAGE-0.1.5.md) 一致，两个资料/混合缓存输入仍不强行判毒。

提供程序故意在每次询问中重复输入公开样本默认密码并选择 Session，共收到 7 次询问。原因依次涵盖首次需要、刚输入失败、重复输入和已有缓存失败，重复包位置未重新弹窗。5 处相同未解密内容记录为 `ARCHIVE-ENCRYPTED-DEFERRED`，不是隐藏或删除缺口。

`ungeond.rar` 和 `TinyWorld.rar` 仍未由该默认密码打开。当前版本不会破解密码，也不会将它们假报为已完成扫描。用户看到明确失败原因后选择跳过时，询问次数会少于故意重复失败输入的回归过程。

## 仍需在云电脑验收

1. 关闭旧版，安装 0.1.6，确认主界面版本和组件完整性检查。
2. 对同一目录重扫，首次选择本次扫描复用，遇到不同内层密码时补充或跳过，检查不再因为相同内容而重复打断。
3. 导出报告，再使用“重试未解密内容”检查重试范围。该操作仅做局部扫描，不替代全机复扫。
4. 按群内测试指南复核真实 DPI、UAC、隔离、Steam 恢复与回滚。本地自动测试不代表这些安装态流程已完成。
