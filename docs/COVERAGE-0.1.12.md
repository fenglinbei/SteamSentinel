# SteamSentinel 0.1.12 检查范围与验收

## 本次修订

执行状态、风险发现、覆盖说明分开呈现。正常触发快速检查边界不再作为风险计数，真正的组件失败、取消、读取受限仍单独保留。JSON 保留旧版 `Coverage` 分类发现以兼容工作进程和密码重试，`RiskFindingCount` 与 `HighestSeverity` 不包含它们，Markdown 和 GUI 分区展示。

## 快速扫描范围

- Steam 客户端、相关进程与启动链、本地所选 AppID 工坊、已识别的 MOD、插件与关联落点，不是全盘扫描。
- 下载、桌面和临时目录仍为额外勾选项，会递归包含其中的资料、样本库与开发目录，文件检出不等于本机感染。不会自动白名单化样本目录。
- 先读取真实格式，目录内优先启动型文件，正常 MP4 检查顶层结构与尾随数据，不整文件哈希，不能排除媒体箱体内的未知内容或播放器漏洞。
- 主哈希预算 1 GiB，单文件完整读取上限 256 MiB。主预算不足时，为不超过 8 MiB 的启动型文件额外保留最多 128 MiB。格式和结构检查仍受枚举、解析器等安全上限保护。
- MP4 尾随内容与格式伪装仍输出启发式告警，压缩内容继续在 Low Worker 中读取。若外层文件未完成哈希，内层威胁不开放 GUI 隔离选择，应补查外层文件，Broker 的身份核验不放宽。

## 未检查内容与补查

主列表仅显示风险与提示，覆盖记录按原因汇总到“未检查内容”，记录数不等于威胁数，也不一定等于文件数。选中一类可查看位置、原因和下一步，界面最多预览 50 条，报告保留完整记录。

“使用完整内容扫描以覆盖此项”对该组现存的本地外层文件或目录启动独立内容扫描，开启压缩内容检查，使用 8 GiB 哈希预算。开始前提示导出旧报告与范围限制，这不是全机复扫，也不会据此解锁完整复扫后的永久删除门禁。

加密内容需要正确密码。损坏文件、不支持的格式、访问受限、压缩比、层数、条目与展开体积上限不会自动解除，补查仍可能得到覆盖缺口。

## 验收重点

1. 大量正常壁纸：不因媒体哈希耗尽预算，未检查内容汇总显示，不形成几千条风险。
2. 超过 256 MiB 的结构正常 MP4：结构检查继续，说明未做完整比对，补查小型媒体可完成整个文件哈希。
3. 改后缀程序和 MP4 尾随载荷：预算不足也保留格式与尾随特征，不能把真正异常混入普通覆盖提示。
4. 压缩包跳过、错密码、不同内层密码：保留重试机制与外层路径。
5. Worker 无握手、取消、读取受限：不显示安全结论，报告保留阶段和退出码。
6. 窗口最小尺寸与普通权限：常用操作可见，高级选项默认折叠，处置权限策略不变。

测试仅运行无害夹具和只读检查，不执行真实恶意样本，不操作真实系统隔离。安装升级、实际目录补查体验和感染云机恢复仍需用户验收。
