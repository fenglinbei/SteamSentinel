# 0.1.7 安装权限与提权回归

## 根因与修复

原写权限掩码含 `FullControl` 与 `Modify`，这两个组合值也包含读取权限。使用按位与检查任意交集，会让 `ReadAndExecute | Synchronize` 也命中写入门禁。

新掩码只包含写入数据、追加数据、写入属性、删除、修改权限、取得所有权及 GENERIC_WRITE/GENERIC_ALL，不包含读取、执行、读取权限或同步。真正的 Modify 和 FullControl 仍通过其中的写入位被拒绝。

权限检查不修改 ACL，仅继承而不作用于当前对象的 ACE 不参与该对象判断，子目录和文件单独检查。NULL DACL 不放行，非受信任所有者、用户或自定义组的有效允许写入 ACE 不放行。检查采取保守策略，不用 Deny ACE 抵消不安全 Allow ACE。

提权前检查完整清单中的文件，包括 .NET 程序集与运行时配置，而非只校验三个 apphost EXE。清单自身 ACL、成员路径、子目录权限、重解析点和 SHA-256 也必须通过。该清单没有发行者签名，不能替代 Authenticode 或外部安全审计。

- 在未提权账户令牌下，对既有 `C:\Program Files\SteamSentinel` 只读执行新版检查，通过全清单验证，第一次测量约 1.4 秒。没有修改原安装 ACL，也没有用放开写权限的方式修复。
- 6 组读取权限、13 组实际写权限、14 组 ACL 描述符、清单路径规范化/重复项、固定提权启动请求、UAC 取消/拒绝/无进程、跨 SID 计划拒绝和 WPF 按钮状态回归。
- 原有 ZIP AES、传统加密 ZIP、RAR、7z、混合密码、部分覆盖、坏包继续扫描及真实 Low Integrity + Job 工作进程测试继续通过。
- UAC 的同意/取消结果通过注入模拟启动器验证，不代表实际安全桌面或另一管理员账户已实测。未在本次回归中操作真实隔离目标。

## 用户路径

普通权限扫描不要求授权。拆分令牌的管理员账户在确认处置后自动进入 UAC，也可主动点击“打开管理员窗口”。标准账户使用按钮请求 Windows 凭据提示，在新窗口重新扫描，避免把旧账户的报告、密码和计划交给另一账户。

原窗口保留，取消授权不丢失报告或选择。启动器只接受内置 EXE 路径和固定窗口标记，不接受目标路径、任意命令、报告、计划或登录凭据。用户在 Windows UAC 中输入凭据，工具不收集密码。

安装检查未通过时，提权和处置都保持关闭，扫描与报告导出仍可使用。修复安装后可点“重新检查”，检查在后台执行并保留原报告。刷新状态不能代替执行前 Broker 的二次核验。

## 安装后的最小验收

1. 退出旧版，安装 0.1.7，不要单独替换 EXE。普通权限启动后等待“安装检查通过”，先做一次无害文件扫描。
2. 点击“打开管理员窗口”，取消 UAC，确认旧报告和勾选保留。再次点击并同意，确认新窗口显示管理员状态，无自动处置。
3. 新窗口重新扫描无害测试文件，确认 Worker 可运行、精确目标可预览、管理员确认后可隔离，随后回滚且不覆盖已存在路径。
4. 使用真正标准账户输入另一管理员凭据，重新扫描前核对原用户 Steam/工坊目录，不要依赖另一账户的自动发现结果。
5. 在普通权限管理员账户窗口直接预览处置，确认 UAC 仍能自动出现。已经提权的窗口不重复提供提权按钮。
6. 核对便携包不能提权，真正可写/缺失组件仍不能处置。不要为测试删除真实组件或放宽生产安装目录 ACL。

真实 UAC、标准账户、升级、隔离、Steam 恢复、回滚和高 DPI 环境仍需现场验收，本版本尚未签名，适用于群内受控测试。
