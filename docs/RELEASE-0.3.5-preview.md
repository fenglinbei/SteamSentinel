# SteamSentinel 0.3.5 本地预览

2026-11-11 · 本地交付，尚未外部发布。规则版本 `2026.11.10.1`。

本轮将“检测到了什么”与“用户允许处理什么”分开，增加保守／激进模式、Steam 配置精确修复及已知恶意内嵌载荷的加载链核验。保留 0.3.4 的已确认 Steam 脚本尾段修复、备份与复验。

## 处置模式

| 模式 | 行为 |
| --- | --- |
| 保守（每次启动默认） | 按已验证证据提供清理和配置修复；其他可疑文件保留复核状态。 |
| 激进 | 允许用户主动选择符合安全范围、具备精确哈希的可疑实体文件；不会把原发现改成已知恶意。 |

切换模式清空当前勾选。激进新增项不默认勾选，用户需重新选择并查看同一次预览中的完整动作。对所选文件，已观测的同文件进程以及直接启动同文件的 Run／RunOnce 可作为关联动作列入预览；不按 `361`、`Application Frame Host.exe` 等名字单独判定恶意，也不追删间接命令链。

预览、管理员最终确认、病例和记录包都显示处置模式及“用户选择处置”标记。扫描规则、分数、风险定性和原始证据保持不变。普通扫描 JSON／Markdown 仍描述原始检测；执行策略见病例及包含计划的记录包。

激进模式可能误隔离合法软件或扩展。文件和被修改的配置会保留备份及恢复记录；停止进程无法恢复其未保存状态。先查看每个目标及影响，不需要为了使用该模式调整系统权限或关闭安全检查。

## Steam 配置修复

- `steam.cfg`：只清除被识别为启用禁更或强制离线的设置，涉及 `BootStrapperInhibitAll`、`BootStrapperInhibitV3`、`BootStrapperForceSelfUpdate` 和 `ForceOfflineMode`；保留其他设置、注释、换行及支持的编码。修复不再要求必须同时出现旧版的两项组合。
- Steam 根目录 `.cef-enable-remote-debugging`：可在确认后备份并移除此单个标记。合法界面扩展也可能使用它，出现标记本身不证明感染。
- Run／RunOnce 和支持的 `.lnk`：确认目标为已发现安装中的 `Steam.exe` 后，仅移除完整的 `-cef-enable-debugging` 参数，保留其他参数。无法确定目标、参数边界或快捷方式结构时不会猜测修改。

配置修复是恢复用户选定的设置，不是将配置声明为恶意。退出 Steam 及 Steam Web Helper 后，核对预览，再执行。管理员执行端重新检查路径、文件／父目录身份、当前字节或注册表原值，并独立计算预期修复结果；快照变化会拒绝执行。

## 宿主和脚本证据

新的强证据检查确认宿主入口从自身资源读取完整已知恶意 SteamAlert Core，跟踪同一字节数据经过复制、程序集加载及载荷入口调用。仅存在相同字符串、未使用资源、其他程序集加载或无关联调用不足以触发该规则。整宿主未必命中已知哈希名单，因此保留这一身份区别；具备该完整证据且经独立核验的实体宿主，在保守模式也可隔离。

归档成员可以报告这条强证据，但当前未实现该规则的外层容器管理员复验，因此保守模式只复核。激进模式允许用户选择具备外层哈希且通过安全检查的实体归档；这仍属于用户选择处置，不代表外层归档本身命中已知恶意哈希。

仅命中托管行为组合的90分结果仍是可疑结论。保守模式继续复核；激进模式允许用户对精确实体目标作处置选择。

已确认的固定 Steam 脚本注入尾段可备份后精确修复，保留其他字节并检查修后哈希。仅重启 Steam 不保证所有被改写 chunk 自动恢复。若仍有可疑下载器、宿主或核心来源，界面明确提示“来源未处置，可能再次修改”；单个脚本修复成功不代表感染来源已全部清除。订阅、其他本地副本或未覆盖的来源仍可能使文件再次出现。

## 回滚与限制

受信隔离事件保留原目标、哈希和动作信息。回滚重新核验备份及当前目标，拒绝覆盖后续变化；扩展范围仍需满足原有元数据恢复条件。恢复可疑程序可能重新使它运行，应先确认是否为误报。旧报告、旧病例及旧计划不会自动获得新模式授权，也不会自动重放。

两种模式都保留系统受保护文件、关键路径、工具及状态目录、网络／设备路径、重解析、多个硬链接和不可完整恢复元数据的边界。用户选择不会放宽这些限制。未完成读取、目录、无精确实体哈希或不能绑定外层身份的内容不能凭分数直接进入隔离。

修复支持已实现的配置和脚本结构，不能保证恢复所有 Steam 版本、第三方扩展或未知篡改。配置／文件修复后需按原范围复扫；完整扫描的覆盖状态也不是整机无毒保证。

## 本地预览身份与验证

使用同一构建生成的完整安装包，升级前退出主程序和管理员窗口。核对随包版本、构建身份、签名说明、SHA-256 清单及测试结果；不要混合不同版本的 EXE／DLL。当前预览不改变公开发行页或稳定版指向。

源码包含双模式策略、配置变换、已知内嵌载荷、双语界面及小窗口布局的专项验证。最终通过数量、测试缺口和签名状态以本次交付的实际构建记录为准；没有把后续重启观察或真实感染主机恢复效果当作已经完成的验证。
