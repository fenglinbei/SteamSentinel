# 下一阶段开发规划：全部 Steam 创意工坊

状态：已记录，尚未实现。更新日期：2026-09-04。

## 当前覆盖边界

当前自动发现仅枚举每个 Steam 库中的 `steamapps/workshop/content/431960`（Wallpaper Engine），并单独处理其本地 projects 目录。已经支持多个 Steam 库，不代表已经支持所有游戏的工坊。SteamSentinel 手动指定其他目录的扫描能力，也不等同于自动覆盖全部工坊。

本次图标版本不改变上述范围，不把未来能力写成已完成功能。

## 目标与分工

“全部 Steam 创意工坊”指本机所有已发现 Steam 库中、所有 App ID 的已下载项目，即 `steamapps/workshop/content/<AppID>/<PublishedFileID>`。不主动联网遍历整个平台，不自动订阅或下载陌生项目。

- SteamSentinel：对通用工坊内容提供扫描、魔数与伪装识别、受限归档解析和密码复用，保留启发式辨别、精确目标隔离及现有 Steam 恢复能力。
- IsMySteamSafe：扩展工坊来源关联、相关运行映像和启动项核对、证据导出，保持快速、只读，不因此加入全量递归解包或自动查杀。

## 实施顺序

1. **全库发现与身份记录**：遍历所有数字 App ID 目录，建立 LibraryRoot / AppID / PublishedFileID / 精确路径的数据模型，处理重复路径、离线库、权限不足和损坏元数据。游戏名称优先从本地 appmanifest 读取，缺失时显示 App ID。
2. **通用内容与专用适配分离**：保留 Wallpaper 的 `project.json` 适配器，其他游戏没有该文件不能视为异常。通用引擎复用已有内容规则，不能仅凭 DLL、EXE 或脚本存在就判定正常 MOD 有毒。
3. **扫描体验与覆盖说明**：快速扫描不默认退化为全部工坊深扫，单列完整工坊扫描及指定游戏/项目选择，显示游戏、项目、进度、跳过理由和未完成范围，支持取消，沿用本次扫描密码复用。
4. **关联与处置**：把全 App ID 范围应用到运行进程、模块、启动项及报告来源字段。SteamSentinel 的处置仍绑定命中成员、真实外层容器与扫描时身份，不按父级工坊目录一键删除，不移除无关游戏或订阅。
5. **最小验收后受控发布**：先完成现有环境可行性验证，保留独立 Worker、资源限制、Broker、安装权限与 TOCTOU 防护，不为扩展覆盖而放宽安全门槛。

## 最小验收清单

- 两个 Steam 库、至少三个 App ID，包含 Wallpaper、普通 MOD 及资源型项目，均能发现且来源不混淆。
- 非 Wallpaper 项目没有 `project.json` 不误报，正常 DLL/脚本不凭扩展名确认为恶意。
- 换 App ID、改项目名或重打包后仍按实际内容命中，不能只依靠样本文件名。
- 无害嵌套加密包支持跨项目复用密码，错误密码、跳过、损坏包和取消均明确记录覆盖缺口。
- 符号链接/目录联接不逃出既定根，权限不足、离线库、大型包及缺失元数据不拖垮整次扫描。
- 处置前文件变化会被拒绝，隔离范围不扩大到整个游戏工坊目录，回滚规则保持有效。
- IsMySteamSafe 能从非 Wallpaper 工坊关联进程和启动项，仍不执行、解包、隔离或上传内容。
- 云电脑进行普通权限与管理员窗口流程核对，保留耗时、覆盖报告与失败信息。恶意样本仅在独立测试环境使用，不在日常电脑执行。

## 暂不纳入

自动下载整个 Steam 创意工坊、依赖在线 Steam API 的强制流程、驱动级常驻监控，以及“所有格式都可解包”或“扫描通过即绝对安全”的承诺。
