# SteamSentinel 0.1.15 范围与验收

本版只修复应用线程与等待体验，不改变恶意判定规则、Broker 处置授权、安装保护或隔离格式。

## 闪退原因与修复

0.1.14 的处置后复查在 `Task.Run` 内创建 `Progress<ScanProgress>`，回调未捕获界面同步上下文，随后在线程池修改 `TextBlock`，引发未处理的跨线程异常。处置结果可能已经保存在受保护目录，但主窗口尚未完成系统复查就退出。

本版使用显式窗口 Dispatcher，后台创建或调用也只能在界面线程更新。密集进度合并为最新一次，阶段结束、取消关闭或窗口已关闭时丢弃迟到更新。显示回调异常与真实扫描异常分开处理，后者仍返回调用方并保留未完成状态，不把异常吞掉后显示成功。

## 等待反馈

- 窗口上方固定显示忙碌状态，不会随结果列表滚动消失。
- 生成方案、处置并验证、系统复查分别显示当前阶段。没有可计算的总进度时使用旋转图标和流动条，不使用假百分比。
- 显示本阶段已用时间，不显示猜测的剩余时间。等待超过 20 秒会说明仍未返回结果，动画只表示界面在等待，不保证后台持续推进。
- 等待用户确认时停止动画并明确提示，不冒充仍在后台处理。系统关闭客户端动画时保留静态状态与计时。
- 方案构建、等待管理员组件、关联查询及报告序列化在后台进行。界面控件访问留在界面线程。
- 只读扫描和方案准备可取消，取消后等待清理完成再关闭。管理员处置及后续复查期间不允许直接关闭窗口，不添加强制杀进程、强制解锁或自动回滚。

管理员组件内部的单项动作和两轮验证仍由原结果协议报告，动画不代表新的实时逐动作进度协议。UAC 安全桌面由 Windows 控制，本工具无法在该桌面继续显示动画。

## 日志与旧结果

错误日志尽力写入 `%LOCALAPPDATA%\SteamSentinel\Logs\error-*.log`，仅本地保存，不自动上传。每条最多 16 Ki 字符，最多保留 50 条，不覆盖旧日志，达到数量上限后需要用户自行保存或整理再继续记录。过滤已识别的凭据，但日志仍可能包含个人路径，分享前请检查。严重内存不足或系统直接终止进程时不能保证写入日志。

旧版已写入的 `%PROGRAMDATA%\SteamSentinel\Results` 和 `Quarantine` 不会因升级清空，也不会自动重做上次计划。崩溃前只在内存中的扫描与完整记录包上下文不能自动恢复，仍需保留现有结果和重新扫描。

## 回归与人工验收

新增用例在真实 STA / WPF Dispatcher 消息循环中安全重现旧错误，并使用实际生产复查入口验证后台上报、界面响应、动画时钟、计时、失败、取消及窗口关闭后的回调处理。复查使用无害模拟数据，不执行 Broker 实际隔离，也不运行病毒样本。离屏界面检查覆盖最小窗口下的各阶段与常用按钮。

使用安装包覆盖升级后，可继续在已准备的测试副本目录中扫描并确认处置，观察方案生成、确认、处置、复查及最终结果是否连贯。无需运行样本，不要为了回归将已隔离的真实威胁自动恢复到系统位置。若仍异常，请保留 Results、隔离清单、本地错误日志和 Windows 事件记录。
