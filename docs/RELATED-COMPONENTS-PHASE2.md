## 扫描结束前补齐内容与运行关系

正常扫描的系统阶段增加只读组件发现。读取当前用户及机器的 Run/RunOnce、启动目录文件或 LNK、任务 XML、服务 ImagePath 与 ServiceDll，保存来源位置、原始命令、工作目录、用户作用域和解析状态。相对路径必须具有明确工作目录，环境变量来自对应身份的快照。无法取得实际进程命令行或工作目录时保留未知，不借用启动项参数冒充进程运行参数。

对有明确种子、启动目标或组件目录线索的宿主进行有界模块枚举；保留 PID、启动时间和映像路径。宿主身份在枚举前后不一致时，只留下未绑定的路径候选。系统受保护路径不占内容候选名额；精确种子和组件目录中实际观察到的模块优先于普通启动程序。签名宿主仍会产生未知 DLL 内容候选。

原内容扫描结束后，主窗口调用关联管线：重核内容证据、重新收集相关观察，再把新增精确文件交给现有 Low Integrity 工作进程检查，最多追加两轮。最后再进行一次证据关联收尾，不开始第三轮内容扫描。扫描前取得的发现超过 64 条时，按路径与哈希去重，并优先处理新增或尚未闭合的证据，避免旧发现挤掉新模块命中。

新文件在补查前使用拒绝写入、删除的只读句柄计算 SHA-256，并持有句柄直到该批内容结果返回。关联旧内容结果前也重新核验当前磁盘文件；同一路径换成另一个哈希时，旧发现不连接到新宿主，当前身份重新进入内容检查。占用、权限不足、文件变化、取消与预算耗尽均保留具体对象和缺口。单个目标是否完成依据它自己的内容摘要；其他目标或签名检查失败不会抹去它的已完成记录。

主报告保留原扫描模式、范围与内容设置。补查结果追加回同一报告；工作进程失败或取消时保留已有片段。正常扫描无需先进入处置预览即可得到新的宿主、持久化与模块关联。

## 证据层级与权限

| 层级 | 本批含义 | 处理资格 |
|---|---|---|
| 观察记录 | 来源命令、路径、宿主、签名或普通 MSI 结构 | 不据此授权处置 |
| 关联风险 | 精确文件内容风险与经核验的路径观察，或受支持 MSI 声明关联 | 新增关联本身只供复核；原内容规则的权限不变 |
| 已确认目标 | 已有可操作的已知恶意内容证据与当前精确身份相符 | 仍须既有计划及 Broker 的执行前重核 |

关系图中的 `SourceReferencesFile` 是字面引用，`SourceAndHostImagePathMatch` 是路径相同，`ObservedLoadedModulePath` 是稳定宿主枚举得到的模块路径。它们不证明某个入口启动了这个实例，不证明进程内存与当前磁盘文件字节一致，也不证明该进程写入代理或证书。不同时间的观察和文件核验时间分别保留。

PAC、IP、文件名、同目录、自签证书或合法签名均不单独增加隔离资格。本批没有增加未知 DLL 的通用恶意哈希、代理/证书写入者规则或新的 Broker 处置权限；也没有声明覆盖本案三个真实 MSI 的全部运行行为。

## 离线宿主签名

宿主路径的现存 EXE/DLL 由受限工作进程检查。使用同一只读文件身份句柄计算哈希并执行 Authenticode，启用本地缓存限定 `WTD_CACHE_ONLY_URL_RETRIEVAL`，不进行吊销检查。新入口与原安装安全检查入口分开，默认 Core 协调器不启用签名探针，只有 ArchiveWorker 显式启用。

`Valid` 表示在当前本地信任与缓存条件下通过，不表示文件或模块安全；未签名是观察，离线信任失败或缓存不足保留 Failed/NotChecked，不推定篡改。失败会同时进入宿主诊断缺口。签名观察回填后，内部传输用的辅助发现不混入普通风险列表。

## MSI 静态分析

使用固定只读表查询，保存每张表的 Complete、NotPresent、Failed 或 LimitReached 状态。补充 Property、Directory、Component、Registry、Shortcut、ServiceInstall、ServiceControl、Binary 名称、File.Sequence、Media 及动作序列表等结构，将 File→Component→Directory 和 CustomAction→Property/Binary/File 对应起来。

动作类型、源引用、条件、序列位置、回滚/提交等标志分别解释。属性传播只支持同一正常正数序列中、顺序明确、无条件且执行上下文明确的前置 Type51 赋值；跨 UI/Execute 序列、同序号、后置赋值、未求值条件、延迟动作及复杂运行时属性保留未解析。Type34 的目录引用不作为可执行命令文本。

每条原始动作独立检测已有内容规则，互不关联的动作不拼接成行为链。新增的属性/成员关联信号为 RelatedRisk、仅供复核；单条已有内容规则的权限保持原边界。成员读取或预算失败仍保留已读出的结构及缺口。MSI 中未出现 PAC 或证书不排除运行后设置；检查不安装 MSI、不执行自定义动作，也不联网取外部分卷。

## 资源与报告边界

| 项目 | 默认限制 |
|---|---|
| 累计来源 / 宿主 / 精确候选 | 512 / 32 / 128 |
| 单次发现的进程 / 每宿主模块 | 2048 / 256 |
| 每来源解析目标 / 来源记录文本 | 128 / 96 KiB；超限明确记录未完整纳入 |
| 新增内容补查 | 最多 2 轮；每轮最多 4096 个内容文件和 2048 个归档成员 |
| 关联核验、补查及展开计账 | 单文件 256 MiB，累计 1 GiB |
| 每次证据闭合或当前身份复核 | 最多 64 个不同精确文件 |
| 发现快照正文 | 每项最多 256 KiB，每次发现共用 8 MiB |
| 时间 | 每次发现 15 秒；原内容阶段结束后的关联补查共用 90 秒 |
| 宿主签名 | 每轮最多 32 个路径，每文件 16 MiB；从关联剩余预算划出至多四分之一且不超过 128 MiB |
| 累计关系 / 检查说明 | 4096 / 2048 |
| 关联传输 | 每片一条记录，单通信帧小于 1 MiB，累计文本 16 MiB |

1 GiB 是关联阶段的核验、受限补查和展开计账上限，不包括此前原内容扫描或每次有独立 8 MiB 限制的发现快照读取。WinTrust 不提供实际 I/O 计数，因此签名按实际哈希字节再加一份文件长度计入保守逻辑预算；报告不把它称为真实磁盘 I/O。同步原生调用只在前后协作检查时间，时间配置不能保证强制中断正在执行的本机调用。

来源列表、字段组合或原始快照超过报告限制时，保留位置和超限状态，说明原始内容未完整纳入，不用被截断的命令继续推断。关联记录以独立分片传输，校验用户、限额、类型化 ID 引用、累计文本和结束帧；不完整片段不能宣布整份报告完成。

界面新增“组件关联”页，展示来源、宿主、候选原因、核验时间、内容状态和各轮预算。详情与导出显示证据层级及处理资格；进一步检查仅允许真实本地精确文件。Markdown/JSON 报告保留关联信息，完整记录包另存最新 `related-components.json`，处置前 `scan.json` 的历史内容保持不变。显示文本有长度限制并提示省略；完整 JSON 仍保留结构化记录，已识别凭据采用现有隐私规则隐藏。
