# 0.3.0 处置入口与历史结果恢复修正

更新：2026-09-28。产品版本仍为 0.3.0；规则不变。本文件描述 preview.3 之后的修复，不把旧包验收计为新包验收。

## 用户能直接看到什么

- 能选中风险项但暂时不能处置时，按钮附近直接说明原因并提供下一步，不要求悬停、找日志或理解内部状态码。
- 启动时自动检查上次操作。确认已经结束后，保留历史结果并恢复新处置入口，无需删除病例、手改配置或重新安装来清空状态。
- 上次操作后尚未重新扫描时，提供“重新扫描”，沿用上次范围；一次性恢复内容的导出授权不会沿用。
- 无法确认旧操作已经结束时，提供“检查并继续”。此操作只检查与保存结果，不重新执行旧计划。
- 结果仍未知的历史会明确说明“已结束，结果尚不能确认”。新的扫描和新的处置方案可以继续；不会把未知记录显示成成功、干净或尚未执行。

## 已确认的问题

旧版在真正执行动作之前拒绝某个文件范围，也可能生成 `ExecutionUnknown` 收据。启动时加载该记录的 `PendingPlanIds`，全局阻止新的处置；原结果读取器又拒绝该未知结果，因此重启与刷新不能自行恢复。全选只检查发现项资格，与这个全局门槛不同，于是出现“全选可用，预览处置不可点”。

## 实现与安全边界

1. Broker 的只读预检查与执行分开。只有在确定还没有开始目标变更的边界，拒绝才返回绑定原 PlanId 和计划指纹的 `NotStarted`。初始化、备份或执行阶段的未知异常仍保留 `ExecutionUnknown`。
2. 原 `ProtectedRemediationResultReader.TryReadAsync/Validate` 的严格成功/完整结果语义不放宽。新增关闭通道读取，只接受严格绑定身份的结束收据；未知分支限定为原 Broker 外层异常格式：失败、空动作、非空错误、完整时间、无成功验证或清单声明。
3. 检查结果路径、当前 SID、保护权限、计划指纹以及最终文件句柄。读取句柄拒绝并行写入/删除；Broker 在释放全局执行锁之后才关闭独占结果文件。活动、缺失、截断、字段缺失、身份不符或权限不可信的结果不能解锁。
4. 先保存病例结果，再解除客户端执行中门槛。磁盘写入失败继续阻断。原受保护收据和计划身份保留，同 PlanId 的 CreateNew 防重放机制不变。
5. 已结束的未知结果存入既有 ExecutionResults，移除对应 PendingPlanId；结果和病例仍为未知。每次启动仍从受保护通道重新核验，不凭用户可写病例中的“已经结束”字段授权。
6. 记录已结束处置的时间；当前报告或延迟到达的报告若早于该操作结束，必须重新扫描。新方案仍执行原有证据、范围、哈希与管理员核验。
7. 批次中途未知会停止剩余批次；对应目标为 `ReviewRequired / remediation.outcome_unknown`。旧计划不续跑、不重放。

## 状态与显示

未新增病例格式或变更旧枚举编号。新增原因码 `remediation.outcome_unknown`；UI 的入口状态和操作类型使用独立枚举，最后映射中英文资源。判断不读取错误文案、按钮文字或翻译内容。

## 验证范围

专项覆盖纯预检查/实际执行边界、独占通道、计划绑定、原严格接口、旧病例持久化与重开、保存失败、篡改/缺失收据、未知状态保留、原批次停止、中英文操作入口及报告新鲜度。

- 恢复专项：89 项通过，0 失败、0 跳过。
- 中文 100% 和英文 150% 合成 DPI 布局分别 454 项通过，0 失败；包含 784×460 小窗口。最后仅收紧进度条上间距，完整构建仍重跑中文回归。
- 中英文资源：3,526 对，缺失、参数和未引用键检查均无错误。
- 用户提供的扫描证据保持 107 条发现、61 条有处置资格；实际受保护旧收据可读，原严格校验仍拒绝其未知结果。当前已恢复状态与内存中显式重建的待确认情形分别核验，不把重建当成真实磁盘状态。
- UI 测试已统一隔离 WPF 自动启动窗口，并在消息循环前后检查。修复后的布局测试和只读真实记录验证均核对病例、摘要与原始结果前后哈希不变。

最初复验曾因 WPF `StartupUri` 隐式创建真实窗口，触发一次真实旧病例的自动恢复：仅更新待确认列表和对应病例摘要，原未知结果保留，没有重新执行处置。该测试隔离缺口已修正，变更与原始哈希保存在私有验收记录中；不宣称整轮验收从未写入宿主记录。

本地修复包使用独立源码快照和自签名，产品版本仍为 0.3.0。完整原生回归、安装器文件/权限回归与机器状态回归均由正式构建脚本强制执行；本包身份、源码树及实际计数以同包 `RELEASE-METADATA.json`、`SELFTEST-RESULTS.json` 和安装器结果文件为准。未用旧包通过记录替代本包门槛。

本轮不扩大自动隔离范围、不降低强证据门槛、不恢复退役弱规则的处置资格。Windows 10/11 历史安装验收、跨物理显示器暂停等既有记录保持各自适用构建范围。
