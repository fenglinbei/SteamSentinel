# SteamSentinel 威胁模型（0.1.8）

## 资产与信任边界

需要保护的资产包括 Steam 会话和库存、浏览器与支付凭据、Windows 安全配置、用户文件，以及隔离区中的取证证据。主要不可信输入是创意工坊项目、伪装媒体、压缩包、脚本、文件名、项目元数据和用户提供的压缩包密码。

主界面默认以普通用户权限运行，也可通过 UAC 打开管理员窗口。两种情况下内容解析均发生在独立的低权限 `SteamSentinel.ArchiveWorker.exe` 中，处置写操作仅由 `SteamSentinel.Broker.exe` 在授权后执行。计划目录属于用户态，隔离区与结果目录在 Broker 写入前收紧为管理员态。管理员处置仅在 Program Files 受保护安装、ACL 检查及全清单组件哈希校验通过时开放，便携运行只保留扫描与报告导出。

## 已缓解的攻击面

- 真实格式由魔数识别，减少“改扩展名即绕过”。
- MP4 按顶层 box 边界解析并检查尾随数据，识别媒体后拼接 ZIP/PE 等覆盖物。
- 压缩条目使用随机临时文件，不把不可信条目名直接映射为磁盘路径；独立检测 `..`、绝对路径和路径穿越。
- 压缩解析有嵌套深度、条目数、单条目大小、总展开字节、文件数和压缩比上限；触发限制时结果转为 `Partial`。
- 工作进程使用当前用户的受限令牌并降至 Low Integrity，以挂起状态创建，先加入 Job Object 再恢复执行。Job Object 限制进程数为 1、单进程内存为 1 GiB，并限制剪贴板、显示设置等 UI 能力，在主进程退出时终止。
- 新受限令牌的默认对象权限只授予当前用户与 SYSTEM，所有者为当前用户，不继承管理员来源的默认对象权限。调用方令牌、安装目录 ACL、系统权限不因扫描启动而改变，初始化失败不会回退到高权限解析。
- 主程序只在工作进程回报 Low/Untrusted 完整性级别后发送扫描路径。工作进程使用精简环境变量和 LocalLow 临时目录，安装器按精确程序路径添加入站与出站防火墙阻断规则。
- 密码通过匿名管道中的 JSON 消息传递，不进入命令行、磁盘报告或日志，可选复用只存在于本次扫描进程内，分为当前层、当前外层文件及嵌套包、本次扫描所有包。仅复用已验证成功的密码，重复失败/跳过内容按哈希合并，未解开时保留覆盖缺口。
- Broker 将用户态计划与请求者 SID、计划 ID、短时有效期及 SHA-256 绑定，路径确认、1 MiB 大小上限、哈希与反序列化使用同一锁定句柄，动作上限为 64。计划改变、文件名与 ID 不一致、UAC 身份变化时均拒绝执行。
- Broker 不再接受调用方提供的结果路径，结果仅以 `CreateNew` 方式写入受保护的固定结果目录。已有文件或新建失败会使用专用退出码通知主程序，主程序不会读取冲突文件。
- Broker 对目标路径、重解析点、PID/映像、文件哈希、目录指纹、注册表视图与当前值、计划任务精确名称与 XML 哈希进行二次校验。计划任务不再使用后缀匹配。
- 进程名称仅用于触发哈希；`ServiceApp.exe` 只有精确恶意 SHA-256 命中时才允许自动终止与隔离。Wallpaper Engine App ID 431960 的多库 Workshop 路径也纳入运行映像哈希候选。
- 同一恶意映像存在多个 PID 时，处置计划稳定排序为先终止全部关联进程，再写入阻断并隔离一次，避免仍运行的副本占用文件。
- 文件隔离锁定同一文件句柄，在该句柄上完成最终路径确认、哈希、复制、隔离副本哈希复核与源文件删除标记。目标文件使用 `CreateNew` 打开并按句柄确认最终路径，减少 TOCTOU 与重解析点替换风险。
- 同卷目录在最终指纹复核后原子移动。跨卷目录先建立快照并校验源/副本指纹，再逐文件重新锁定句柄、复核哈希并删除，目录新增或变化时保留源与副本并报告失败。
- 隔离与结果根目录由 Broker 设为 SYSTEM/Administrators 可写、Users 只读；清单在动作前后原子写入。回滚前会重新验证事件 ID、记录类型、原路径范围、备份路径、哈希及内置规则。
- 回滚拒绝覆盖已存在目标；hosts 修改使用事件边界标记；防火墙规则使用事件与动作 GUID 命名。
- 生命周期动作必须单独提交；含未回滚内容的事件同一启动周期内不能永久删除。

## 明确不做的事

- 不运行、安装、加载、反射调用或沙箱动态执行待检文件。
- 不尝试暴力破解压缩包密码。
- 不自动删除未知证书、用户代理配置、Clash 类工具或其他仅凭环境存在就可疑的软件。
- 不上传样本、密码、Steam 身份信息或支付信息。
- 不承诺发现所有未知恶意代码，也不替代已启用且更新及时的终端防护产品。

## 公开发布前剩余风险

- ArchiveWorker 已使用受限令牌、Low Integrity、Job Object 与安装器防火墙规则，但还不是 AppContainer。Low Integrity 主要阻止向中/高完整性对象写入，并不阻止读取当前用户可读文件；解析器漏洞仍可能读取超出本次选择范围的资源。
- 目录树操作已增加指纹与逐文件句柄复核，但 Windows 目录枚举与同卷目录重命名尚未完全迁移为根目录句柄相对操作，仍有小于单文件处置的 TOCTOU 残余面。
- 三个可执行文件尚未 Authenticode 签名。安装包会写入 Program Files 并运行时校验 ACL 与发行包哈希，但下载到首次安装之间仍依赖发布 SHA-256 和可信分发渠道。
- 规则随程序集发布，尚无签名在线更新、撤回和透明度机制。
- Broker 的“复扫干净”条件由界面控制；Broker 自身强制重启门槛和动作白名单，但尚未对复扫报告建立不可伪造的证明链。
- 压缩格式覆盖取决于 SharpCompress；损坏、特殊加密或未支持格式会被标为 `Partial`，不能据此宣称安全。
- 尚未完成独立代码审计、解析器模糊测试、企业环境兼容性测试和可复现构建认证。

这些项目是正式公开发行前的剩余工作。当前版本的目标是把风险降到适合群内受控测试的程度，不把它表述为已达到专业终端防护或公开大规模分发标准。
