# 0.1.19 密码交互修复

此修复仍使用 0.1.19。保留当前整体设计，在密码窗口补充多密码与本次跳过全部未解密内容的操作，不扩展处置权限，也不执行压缩包内程序。

## 使用方式

- 默认仍输入一个密码。可选“只用于当前这一层”“当前外层文件及其中的嵌套包”或“本次扫描遇到的所有压缩包”。单密码只有在成功读取加密内容后才会成为已验证密码。
- 输入框右侧的眼睛图标可显示或隐藏当前输入，默认隐藏。隐藏时清空明文输入控件，提交、跳过或关闭后清理两种输入状态；候选列表始终遮蔽，不随眼睛按钮显示全部密码。
- 需要同时提供多个密码时，启用多密码选项，逐个加入候选列表，按列表顺序尝试。候选列表遮蔽密码内容；密码中的空格有效，不用逗号或空格拆分。
- 多密码列表是用户明确提供的候选，不等同于已经验证正确。候选按所选复用范围尝试，不会因为某个密码先成功而自动改变列表顺序。单层范围不向内层或其他包传递；外层文件范围不向其他外层文件传递。
- 最多同时提供 16 个候选，每个最多 1024 个字符；完全相同的候选去重，保留首次输入顺序。超限输入会明确提示，不静默截断密码。
- “本次跳过全部未解密包”仅对当前扫描有效。程序仍先尝试适用的密码，对仍无法解密的内容不再弹窗，并保留未检查记录。普通文件与能够解密的包继续检查。
- “跳过这一层”或关闭密码窗口不会自动开启跳过全部。扫描结束后可通过“重试未解密内容”重新提供密码；这是新扫描，之前的密码与跳过全部选择不会继承。

## 安全边界

只尝试用户提供的有限候选，不生成字典或进行暴力穷举。压缩比、深度、单项大小、整轮真实读取及元数据尝试上限继续生效；密码错误可以恢复逻辑计数，但已经消耗的真实读取与尝试预算不回退。

每轮最多执行 512 次带密码的归档解码尝试，在读取加密目录之前就计数，错误密码也消耗额度。达到上限后保留明确的未检查原因，不继续索要无法尝试的密码；无需密码的普通归档仍可检查。可缩小范围后重新扫描，新的扫描会重置额度。失败密码历史仅保留本轮内存中的固定长度带密钥指纹，用于避免对相同内容重复尝试，不写入文件。

密码仅保留在当前应用/扫描进程的内存并通过受限 Worker 的匿名管道传递，不进入扫描报告、日志、命令行或磁盘密码库。界面会清空输入并释放候选引用，扫描完成或取消后清理会话缓存；托管字符串不承诺物理内存逐字节擦除。

未读取、跳过或受限内容仍为未完成检查，不能据此确认安全。正确密码也不能解决内容损坏、格式不支持、权限限制或安全上限。

## 回归证据

使用自行生成的无害 ZIP AES、传统 ZIP、7z、RAR 和混合嵌套样本，验证密码复用、固定候选顺序、跳过全部、新扫描重置、取消和报告不包含密码。`--password-v0119 <新输出目录> [包内Worker路径]` 输出专项 JSON；完整 SelfTest 也包含密码回归。最终测试数量和构建身份以交付包结果为准，不沿用此前文案修复包的验收数量。
