# 0.2.0 容器检查实现与支持边界

日期：2026-09-06。本文描述当前候选源码的实际处理方式；具体通过项、耗时、峰值和构建身份以同一候选包的发布验收记录为准。原始需求、历史基线和验收编号保留在 [ARCHIVE-SUPPORT-0.2.0.md](ARCHIVE-SUPPORT-0.2.0.md)，不将实现说明替代验收结论。

本专项解决 MP4 尾随归档、改名归档、RAR/ZIP/7z 分卷、多层 SFX 和大文件的继续检查。所有内容处理都沿用受限 ArchiveWorker；主界面只显示元数据、请求密码和在用户主动选择后交付恢复副本。内容识别、完整性验证和恶意性判断分别记录。

## 1. 容器链与原始目标

`ContentScanner` 将每层表示为 `ContainerScanNode`，由 `ParentId` 组成来源链。

| 节点种类 | 记录内容 | 偏移含义 |
|---|---|---|
| File | 用户原始文件、完整内容 SHA-256（如本次完成哈希）、原始处置目标 | 原始文件自身 |
| EmbeddedRange | 已识别的 MP4/PE 外附归档范围、格式和长度 | `ParentOffset`、`ParentLength` 相对直接父层流 |
| ArchiveMember | 成员逻辑名称；完成解码时记录实际长度及内容 SHA-256，超限跳过时仅有目录声明长度 | 压缩成员通常没有可直接换算的原文件物理偏移，字段留空 |
| VolumeGroup | 已限定的卷序列、各卷原始路径/大小/SHA-256、卷组身份 | 保留完整卷组；不伪造跨卷连续物理偏移 |
| UnknownRange | 未归属字节范围、相对偏移、长度、独立 SHA-256/适用内容引擎结果及未解析原因 | 范围识别与格式完整性仍是缺口；引擎执行完不将其改成已验证归档 |

嵌套临时文件名由程序生成，只使用编号和 `.scan` 后缀；成员原名保留在逻辑显示路径中，不用其创建磁盘路径。临时卷身份会标记为临时来源，界面补查回到真实原始外层文件或卷组。

`Sha256` 是本层内容身份，`OriginalTargetSha256` 是原始外层身份，两者不能互换。命中项在发送检查点前绑定 `ContentPath`；原件已完成哈希时同时绑定 `TargetSha256`，未完成则保留空值并说明处置条件不足。管理员处置继续复核真实外层文件，不针对临时成员执行隔离。

已完成解码的同一物理卷组可在同一扫描根内复用。缓存同时绑定内容身份、按序物理文件身份、扫描根和原始外层上下文；字节相同的不同原件或分别选择的不同根仍各自检查并保留命中。密码失败记忆继续按内容身份工作，避免复制件导致反复询问。

## 2. 范围识别和格式矩阵

| 输入 | 当前实现 | 不能据此声称的能力 |
|---|---|---|
| MP4 | 验证顶层 box、64 位扩展长度、`size=0` 延伸至 EOF；在媒体边界外识别归档和残留范围 | 不分析媒体 box 内任意隐藏载荷；内部魔数不等于尾随归档 |
| PE / RAR SFX | 按 PE 头、节数据、证书表文件偏移和 WIN_CERTIFICATE 记录界定映像；分别检查证书表前后附加范围 | 不启动 SFX、不执行 Setup；不能把证书表当作归档尾部 |
| ZIP / ZIP64 | 对照本地头、中央目录、结束记录、大小与偏移；支持受验证的数据描述符与 ZIP64 字段 | 不支持的扩展布局保持缺口；不是所有能被解压软件容忍的 ZIP 都被接受 |
| ZIP 加密 | 传统 ZipCrypto 使用完整成员长度及 CRC32；AES AE-1/AE-2 验证参数和认证码，按格式要求核对 CRC | 短密码校验字段通过不能替代完整校验；AE-2 无明文 CRC 时不伪造 CRC 通过 |
| ZIP 分盘 `.z01` + `.zip` | 使用磁盘号和目录偏移语义映射有序卷组 | 不能作为普通字节拼接处理 |
| ZIP `.zip.001`、7z `.7z.001` | 有界收集明确同族卷，构造受限可定位逻辑流并验证格式 | 仅有 `.001`、缺首卷或无法确认命名族时不猜测归属 |
| 7z | 明确输入、完整遍历、实际长度及真实存在的成员 CRC；拒绝缺校验元数据和 anti-item 的完整性声明 | 不以 `IsComplete` 或解码长度单独证明成员完整性 |
| RAR4 / RAR5 | 验证卷头/接续与结束条件，支持编号卷和旧式 `.rar` + `.r00`；处理加密文件名及成员校验，支持已实现的 CRC/BLAKE2/密码关联校验路径 | 未识别加密参数、无法唯一匹配的重名成员和未支持校验方案明确拒绝完整性通过 |
| tar、gzip、bzip2、xz、zstd 等其他单流格式 | 使用受限流、同轮预算和受控临时文件继续静态检查，解码器失败保留缺口 | 当前独立完整性方案未覆盖，节点保持 `UnsupportedIntegrity`；不随三类分卷适配器自动升级为完整支持 |
| MSI / CAB | 保留原有 Windows 只读结构适配器、静态表/动作分析和独立资源边界 | 外部介质、多卷 CAB、特殊压缩及原有 4 GiB 实际展开等限制未因本专项取消；不能宣称新完整性链已验收 |

RAR SFX 配置仅从已通过头/注释校验且可静态读取的注释中提取白名单字段。加密目录或缺结束标记时，仅识别到头不会自动取得精确归档末端；无法确定的剩余字节仍保持未完成。

范围解析另有独立限额：默认最多读取 32 MiB 结构数据、在 4 MiB 窗口中搜索签名/结束候选、128 个候选、100,000 个记录、单头 2 MiB、静态 SFX 注释 256 KiB、15 秒。达到任一限额会留下结构缺口，不用无界全文件搜索替代。

分卷查找默认只涉及源文件同目录，以及用户本次明确提供的本地补卷目录。最多 4,096 个目录候选、128 个实际卷；同族重名、混用命名方案、编号断裂、缺卷、路径不可用或源身份变化会单独显示。目录候选不是已验证卷清单，解码器不能自由打开任意相邻文件。

## 3. 五阶段和内容引擎

每个节点分别记录识别、目录读取、解密、完整性和内容检查。五个阶段均为 `Complete` 或明确 `NotRequested`，且必要子节点完成，才可将本层记为 `Complete`。Worker 分片在发送与接收时拒绝“总状态完成但某阶段未完成”的节点。

缺卷、混卷、重复卷、密码待提供/失败、跳过、损坏、不支持、完整性未支持、超限、访问受阻、源变化和取消均保留不同状态。`Complete` 仅表示本次已请求且受支持的检查完成；发现数量为零不是无恶意保证。

| 引擎 | 范围与报告方式 |
|---|---|
| SHA-256 | 固定缓冲流式读取完整本层范围；快速跳过或预算不足会显示未完成哈希 |
| 字符串/行为规则 | 当前整项输入上限 32 MiB；超限明确记录未检查正文，不把哈希完成代替特征检查 |
| AMSI | 当前整项输入上限 32 MiB；提供程序缺失、错误、超限和实际检测结果分开记录 |
| 离线 Authenticode | 对同一只读锁定身份的完整 PE 文件调用离线验证；区分有效、未签名、摘要不匹配、链不受信、离线不足和失败 |

深层签名检查可在界面关闭。原生签名调用的实际 I/O 不可测，按文件长度单独预留工作预算；嵌入 PE 若没有独立文件身份，不以外层句柄冒充该 PE 的签名结果。签名状态不扩大自动处置资格，`HashMismatch` 是完整性异常，`NotSigned` 不是病毒判定。

## 4. 默认预算和真实计量

| 项目 | 快速模式默认 | 完整/自定义内容默认 |
|---|---:|---:|
| 单归档成员 | 256 MiB | 8 GiB |
| 累计逻辑展开 | 2 GiB | 32 GiB |
| 累计工作预算 | 4 GiB | 64 GiB |
| 临时占用峰值 | 2 GiB | 16 GiB |
| 最大嵌套深度 | 4 | 12 |
| 容器协作时间 | 300 秒 | 1,800 秒 |

每轮另有 20,000 个归档成员、20,000 个容器节点、80,000 次元数据尝试、512 次密码尝试、压缩比 500 和 1 GiB 磁盘保留空间。主文件枚举保留 200,000 个文件边界。显式配置和关联补查可比表中默认更窄；界面及报告显示实际生效值。

工作预算包括源流实际交付字节 `ReadBytes`、解码实际输出 `DecodedBytes`，以及不能实测的原生读取/解码保守预留。重复读取、失败密码和已发生的解码均消耗预算。逻辑展开只在内容被接纳时增加，错误密码回滚逻辑结果不会退还读取、解码或尝试成本。

`RangeCopyBytes` 单列复制量，临时占用记录当前值和峰值；释放临时文件后归还实际占用，删除失败仍保持计账。报告中的流字节不是操作系统物理磁盘 I/O；原生预留也不作为已实测读取/解码展示。解码调用可能在最后一次缓冲返回后才知道总预算已耗尽，此时保留有限末块超量并标记未完成，不把超限结果改写为通过。

单成员声明大小或压缩比超限时，ZIP 可以跳过尚未打开的成员并继续后项；跳过节点只保留目录声明长度、无内容 SHA-256，整个归档保持不完整。RAR/7z 不能借此跳过可能关联解码状态的成员，会停止当前归档；已打开成员实际长度超限也会停止当前归档。各情况保留 `ARCHIVE-SIZE-LIMIT` / `ARCHIVE-RATIO-LIMIT` 原因、已验证前缀和确已验证的密码范围，不退还已经发生的读取。累计工作、逻辑展开、临时占用、元数据或时间预算耗尽才停止本轮后续内容。RAR/ZIP/7z 解码取消或耗尽预算时，已通过完整校验的成员先登记 SHA-256、实际长度和未完成阶段，再交回检查点；保存这些已知事实不需要重读临时文件。

ArchiveWorker 保留 Low Integrity、单进程 Job 与 1 GiB 进程内存边界。启动器另有“本轮容器时间 + 5 秒”的独立硬超时，使未返回协作检查点的解码器/原生接口仍会收敛。取消、失败或终止后，已经交回的检查点保留为部分结果。

关联组件自动补查按剩余关联预算构造窄限额，保留签名偏好和明确补卷位置，绝不继承恢复输出目录。预算不足的大目标留下可回到真实外层的补查记录。主扫描与补查合并后保留每轮 ScanId、时间、根路径、节点 ID、限额及消耗，逐轮显示；不把多轮消耗伪装为同一轮共享 64 GiB。

## 5. 界面、补查和导出

“容器检查”页提供可复制的完整路径、父链、五阶段、引擎覆盖、签名、卷身份和资源记录，保留原有其他页面顺序。

- **补查原始外层/卷组**：从当前节点回到原始本地文件，创建本次完整内容检查；不是任意位置断点续解码，也不是全机复扫。
- **选择补卷目录后补查**：明确加入本次可查找的补卷位置，不自动搜盘或下载。
- **选择恢复目录并重扫**：本次主动请求独立恢复输出；历史报告和自动关联补查不会悄悄继承该写出请求。
- **完整记录/导出报告**：展示或导出只读元数据。JSON/Markdown 含节点、父链、状态和计量，不附样本字节。

恢复内容先由 Low Worker 写到本轮专用暂存目录；成功返回后，主程序按节点映射逐个核对长度和 SHA-256，再新建独立输出目录。交付文件使用节点编号加 `.scan`，另有 `evidence.json` 记录原名、身份和检查结果；不覆盖已有输出、不执行恢复内容。中间容器以元数据保留，不自动复制为恢复文件。

复制中途失败或取消时，已交付且核验过的文件仍在输出目录中，节点按实际交付状态更新；证据文件在输出仍可写时生成，写入失败会单独报告。未交付暂存文件不会冒充已保存成果。报告和恢复证据使用相同的秘密文本脱敏规则，密码通过会话内 IPC 传输，不写进命令行、普通报告或恢复证据。

## 6. 尚存边界与验证入口

未知尾部先做有界魔数识别，再在本次额度内独立计算范围哈希和运行适用内容引擎；即使快速哈希预算不足，已识别的 MP4 尾部启动型内容仍可明确提示。未知格式和容器完整性始终保持未支持，不递归猜测新的归档，也不自动交付未知范围字节。工作被中止时，已验证前缀只表明上层成员校验通过，内容引擎尚未运行则记录取消/超限；当前未验证成员和失败密码产物不宣称完成。容器节点容量本身耗尽时，无法登记的成员数量另记证据缺口。

本专项不完成 MSI/CAB 的全部格式兼容，也不扩大证书/代理规则目录、原生修复授权或 Broker 动作。第三批真实样本、重启恢复及干净 Windows 10/11 安装/修复验收，继续遵循原冻结方案和 [第三批交付说明](EXACT-REMEDIATION-PHASE3.md) 的限制。

自动回归使用惰性数据、自建归档、受控签名对照和无大分配的虚拟范围；真实取证内容、密码和恢复游戏文件不进入公开 CI。范围、分卷/校验、资源/分片、来源与检查点、合并/导出和实际 WPF 布局测试分别位于 `SteamSentinel.SelfTest` 的 `V020*` 文件。小体积同拓扑、实体大文件、Low Worker 与恢复交付的结果需绑定同一 BuildIdentity 单独记录；本文不预填尚未完成的测试数字。
