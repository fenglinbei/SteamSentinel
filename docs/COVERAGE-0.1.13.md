# 0.1.13 检查范围与内存修复

本版仅调整 SteamSentinel，不修改 IsMySteamSafe。延续 0.1.12 的快速扫描范围、完整内容扫描、密码复用和处置能力，规则版本仍为 2026.09.04.2。

## 修复依据

用户在完整内容扫描并勾选下载、桌面和临时目录后出现 OutOfMemoryException，旧报告只保留系统阶段。该报告没有内部调用栈和最后路径，因此不能确定是哪个文件或解码器引发了当次故障，也不能据此认定文件被安全软件删除。

## 已实施

- 原来最多 32 MiB 文件会同时产生字节数组、UTF-8 文本、UTF-16 文本与拼接文本，现以 256 KiB 读取块和 144 KiB 重叠窗口分析，仅累积命中信号。原始字符串组合跨窗口、跨编码汇总，脚本文字仍仅静态归一化，不执行命令。保留原有 32 MiB 文本检查上限。
- AMSI 使用单份有界缓冲区，不再复制一份完整文件。读取期间大小变化会如实记作未完整检查。
- 父压缩包在解压本层之后、检查内层之前关闭，避免同时保留多层解码器。密码仅在实际验证后缓存，嵌套与复用规则不变。
- 目录文件按每批 512 项排序，不再一次缓存整个目录排序。文件数量上限同时约束跨目录累计数量。
- 完成外层文件扫描和哈希绑定后发送结果检查点，每批每类最多 64 项，单通信帧最多 1 Mi 字符。接收端在拼接前检查长度，并检查批次序号和列表范围，完整结果必须收到明确完成标记。
- 扫描组件仍保留本轮有界报告，结果或覆盖记录各最多 20,000 项，主要结果文本预算为 8 Mi 字符，单字段 64 Ki 字符。达到限制时停止并提示分批扫描，不静默舍弃风险记录、不将未检查项判断为安全。
- 保持 Low Integrity 和 1 GiB Job 内存限制。组件私有内存达到 640 MiB 时尝试回收，回收后仍达到 768 MiB 则停止。解码器瞬间申请很大内存仍可能越过软阈值，发生异常时保留此前已交回的结果，不能保证任意压缩包永不触发 OOM。
- 取消和异常退出时，系统检查与已交回内容结果一并保留。正在处理的外层文件可能尚未交回，不能将部分结果作为完整干净复扫。隔离仍需原有哈希、安装保护和 Broker 校验。
- 导出报告记录内容扫描设置、最后路径、内部阶段、错误类型/调用位置（能取得时）、内存采样和启动窗口权限。JSON 逐项序列化并脱敏，不再创建整个报告的额外 JSON DOM。密码不写入报告。

## 验证与验收边界

自动回归覆盖跨块与跨编码组合、大文件信号、九千条结果分批往返、乱序与超长通信帧、故障/取消保留、报告脱敏，真实 Low Worker 覆盖连续 32 MiB 无害文件、六千条覆盖结果和跨根目录资源限制。现有密码、压缩格式、检测、安装保护及处置安全测试继续运行。

这些测试不是对原故障目录的完整复现。最终实机验收请退出所有旧版窗口，使用 0.1.13 安装包覆盖安装，先按原设置进行“完整内容扫描 + 下载、桌面和临时目录”。如果仍中断，导出 JSON 和 Markdown，两者现在包含内部阶段与最后路径。可用“扫描目录”分批补查剩余位置，不必关闭安全防护，也不要为验证而运行样本。

保持正常界面文案，只显示版本号。本轮构建的测试统计、成品校验和签名性质另见输出目录交付记录。自签名测试证书不会自动获得其他电脑或 SmartScreen 信任。
