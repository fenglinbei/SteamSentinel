## 资源与语言入口

- `SteamSentinel.Core/Reporting/PresentationMessages.resx`：本批英文中性资源，668 个键。
- `PresentationMessages.zh-Hans.resx`：对应简体中文，键和格式占位符完全一致。
- `StatusMessages*.resx`：上一批 67 个状态模板继续使用。
- `DisplayText`：本地显示资源入口；`StatusPresentation` 使用同一个显示语言上下文。
- `AmsiPresentation`、`RemediationResultPresentation`：按已经记录的代码／枚举解释结果，不解析自由文本。

保持现有应用默认中文；指定中文区域使用简体资源，其他区域使用英文资源。语言选择控件和持久化尚未接入。显示上下文通过有作用域的 `AsyncLocal` 传递，跨 `await` 保留，各并发任务独立；退出或异常后恢复原语言，不改操作系统和线程区域设置。

```csharp
await ReportExporter.ExportMarkdownAsync(report, path, DisplayText.English, cancellationToken);
string containerText = ContainerReportPresentation.Describe(containers, DisplayText.English);
string actionText = RemediationResultPresentation.Describe(actionResult, DisplayText.English);
string amsiText = AmsiPresentation.Describe(amsiDiagnostic, DisplayText.English);

using (DisplayText.UseCulture(DisplayText.English))
{
    // Existing display getters also use this scope; machine values do not.
    string summary = batch.Summary;
}
```

扫描预算的显示定义按中文和英文分别缓存，避免第一次访问时固定成某种语言。产品英文显示名称仅用于展示，不修改 `ProductInfo.Name`、AMSI 应用身份、安装身份或目录名。

资源键属于显示层，不是新的状态或原因协议。既有按源文件／成员分组并带序号的键已固定，后续只追加，不按文案顺序重编号；有枚举意义的资源也不能取代对应枚举。多参数句子放在一个模板中，参数作为数据传入；未知键和格式不匹配回退为含资源键的可读提示，参数中的花括号不再次解释。资源文件是后续维护的来源，工作目录中的一次性提取／生成脚本不能用于覆盖后续修改。

`DisplayText` 只格式化本地显示数据，不扩展跨进程允许的消息参数或记录大小。此前 `StatusMessage` 的参数限制、分片验证、报告预算和 Broker 权限检查继续适用。

## 原始记录的处理

同一报告可以分别生成中英文公共说明，JSON 的规则 ID、哈希、路径、UTC 时间、状态和动作集合保持不变。中文原始标题、证据、系统异常、历史自由文本不会被推测性翻译覆盖。因此含旧记录或尚未迁移的引擎说明的英文导出中，仍可能出现中文原文。

AMSI 从诊断代码生成新的外层解释，并另列原始详情。失败调用即使带有大于检测阈值的原始数值，也不作为有效检出结果显示；空输入不宣称已提交正文供引擎检查。动作返回成功而复验待重启时，继续分别显示执行成功与待重启复验。
